# faRuby

**PLC 上で mruby を動かします。** 名称は FA (Factory Automation) + Ruby に
由来する実験的プロジェクトです。

mruby で書いたプログラムを PC で `mrbc` でコンパイルし、PLC へ転送すると
PLC がそのまま実行します。デバイスは `$DM100` のようにグローバル変数で
読み書きします。

```ruby
$DM100 = 42
$MR10 = true if $DM100 > 10
```

**使えるのは mruby の部分集合です。** 何がどこまで動くかは
[現在の対応範囲](#現在の対応範囲)に、Ruby のつもりで書いたものがどうなるかは
[doc/differences.md](doc/differences.md) にあります。

### 対応 PLC

**4 機種で実機確認しています。**

| メーカー | 機種 | プロジェクト |
|---------|------|------------|
| キーエンス | KV-5000 | [plc/keyence/KV-5000/](plc/keyence/KV-5000/) |
| キーエンス | KV-X500 | [plc/keyence/KV-X500/](plc/keyence/KV-X500/) |
| 三菱電機 | MELSEC Q | [plc/mitsubishi/Q/](plc/mitsubishi/Q/) |
| 三菱電機 | MELSEC iQ-R | [plc/mitsubishi/iQ-R/](plc/mitsubishi/iQ-R/) |

**機種ごとに PLC プロジェクトが入っています。** KV Studio や GX Works で
開けば、VM も設定も入った状態から試せます。接続先を自分の PLC に合わせて
転送すれば動きます。

**プログラムは機種が変わってもそのままです。** 違うのはデバイスの名前
(`DM100` / `D100`) だけで、それも[割り付け表](#デバイスの割り付け)に
まとめれば書き替えずに済みます。

## セットアップ

### 前提条件

- Ruby 3.0 以上
- mruby 3.3.0 (mrbc コンパイラを使用)
- [plc_access](https://github.com/ito-soft-design/plc_access) gem (PLC 通信用)

### Windows は先に C コンパイラを用意する

**素の Windows には入っていません。** `plc_access` が依存する `serialport`
gem がネイティブ拡張なので、無いと `bundle install` の時点で止まります。

**[RubyInstaller](https://rubyinstaller.org/) は Devkit 同梱版**
(`rubyinstaller-devkit-x.x.x-x64.exe`) を選んでください。入れた後、MSYS2 と
MinGW のツールチェーンを導入します。

```
ridk install 1 3
```

**bison は別に足します。** mruby のビルドに要りますが、Devkit の標準構成には
含まれていません。

```
ridk exec pacman -S --noconfirm --needed bison
```

### mruby のビルド

```bash
git clone https://github.com/mruby/mruby.git -b 3.3.0
cd mruby
rake
```

ビルド後、`mruby/build/host/bin/mrbc` が使用できるようになります。

**Windows は先に `ridk enable` を同じシェルで実行します。** MSYS2 の
ツールチェーンが PATH に入り、`gcc` と `bison` が見えるようになります。
**要るのはこのビルドのときだけ**で、できた `mrbc.exe` は単体で動きます。

```
ridk enable
git clone https://github.com/mruby/mruby.git -b 3.3.0
cd mruby
rake
```

できあがるのは `mruby/build/host/bin/mrbc.exe` です。

### 依存 gem のインストール

```bash
bundle install
```

### 設定ファイル

`faruby.yml.example` をコピーして、環境に合わせて編集してください。

**BOM なしで保存してください。** BOM 付きだと YAML の解析が先頭の BOM を
制御文字と見なし、`control characters are not allowed at line 1 column 1` で
読み込みに失敗します。Windows のエディタは既定で BOM を付けることがあります。

```bash
cp faruby.yml.example faruby.yml
```

```yaml
connections:
  current: target1       # いま対象にしている接続先
  target1:
    model: KV-5000
    host: 192.168.0.10   # PLC の IP アドレス

mrbc:
  path: /path/to/mrbc    # mrbc コンパイラのパス
```

**Windows でもスラッシュ区切りで書けます。**

```yaml
mrbc:
  path: C:/path/to/mruby/build/host/bin/mrbc.exe
```

設定は 2 層になっています。`faruby.yml` に書いた項目だけが `faruby_default.yml`
の既定値を上書きし、書かなかった項目は既定値のまま残ります。既定値の一覧と
説明は [faruby_default.yml](faruby_default.yml) にあります。

#### 接続先

**同じ機種の PLC が複数あるので、接続先は名前を付けて並べます。** どれを使うかは
`current` で選びます。

```yaml
connections:
  current: target1
  target1:
    model: KV-5000
    host: 10.0.1.201
  target2:
    model: KV-5000
    host: 10.0.1.202
  target3:
    model: KV-X500
    host: 10.0.1.203
```

名前は自由に付けられます。設備や装置の名前にしておくと、どれに繋いでいるかが
コンソールの表示だけで分かります。

接続先が機種を決め、機種の設定 (実行・メモリ配置) がそのまま付いてきます。
コンソールと `rake transfer` がこれに従います。1 つだけなら `current` は
省けます。一度だけ別の相手にするなら
`ruby tools/console.rb --connection target2`、照合は
`rake transfer CONNECTION=target2` です。

書けるのは `model` / `protocol` / `host` / `port` だけです。**メモリ配置と
実行設定は機種ごとに書きます** (下の節)。設備ごとに配置を変えたいときは
フォルダを分けてください
([doc/architecture.md](doc/architecture.md#設備で配置が違うときはフォルダを分ける))。

デバイスの割り付けもここには書きません。プログラムの隣に置きます
([デバイスの割り付け](#デバイスの割り付け))。

#### 機種ごとの設定

**実行とメモリ配置は機種ごとに持ちます。** 既定値は
[faruby_default.yml](faruby_default.yml) が機種ごとに一式を持っていて、
`models:` の見出しは機種名です。

```yaml
models:
  KV-5000:
    plc:
      protocol: keyence_kv
      host:
      port: 8501
    vm:
      steps_per_cycle: 50
    memory:
      device: EM
      base: 20000
      instances: 2
      ...
```

`faruby.yml` には違うところだけを書けば足ります。共通の位置 (`models:` の外)
に書いた項目はどの機種にも効き、機種の下がそれを上回り、接続先の接続情報が
最後に上書きします。

```yaml
models:
  KV-X500:
    vm:
      steps_per_cycle: 30
    memory:
      base: 24000
```

**設定を変えたら `rake vm_core` で生成し直します。** 全機種ぶんまとめて出る
ので、機種ごとにメモリ配置を変えていればそれぞれの生成物にその配置が入ります。

**生成する言語 (KV スクリプト / ST) と書き出し先は機種で決まり、設定では選べません。**

### メモリ配置

faRuby は PLC のデバイス領域を 2 つ使います。**ラダーが使っていない領域を
割り当ててください。重なると双方が壊れます。**

| 区分 | 内容 | キーエンス | 三菱 |
|------|------|-----------|------|
| 実行中に変わる | 実行の状態、変数、配列 | EM20000- | D4000- |
| 実行中に変わらない | 転送したプログラムと定数 | FM0- | ZR0- |

既定の配置は `faruby_default.yml` に機種ごとに書いてあります。内訳は
`rake console` の `memmap` で確認できます。

```yaml
models:
  KV-5000:
    memory:
      device: EM        # 可変領域のデバイス種別
      base: 20000       # 可変領域の先頭アドレス
      instances: 2      # 同時に実行するインスタンス数
      fixed_base: 0     # 固定領域の先頭アドレス
```

**配置を変えたら `rake vm_core` で生成し直し、PLC へ転送してください。**
アドレスは生成物に定数として焼き込まれます。

#### PLC 1 台ごとの事前設定

**どちらも領域を確保しないと動きません。** 導入する CPU ごとに要ります。

**キーエンス** — KV Studio の **CPU システム設定 → ローカル全体割付設定**で、
**EM のローカルデバイス予約個数を 25535** にして EM0-EM39999 まで使える
ようにします。足りないまま実行すると、最初のインデックス修飾で
**「間接指定が不適切」の演算エラー**が出て止まります。

固定領域の FM は ZF をバンクに分けたもので、**使うバンクは機種ごと**です。
KV-5000 はバンク 3 (スクリプトが `FRSET` で選びます)。**KV-X500 にはバンクを
選ぶ手立てが無く、常に 0 です。** ラダーがバンク 0 の ZF を
使っていると壊します。

**三菱** — ファイルレジスタ (ZR) の容量を確保し、**デバイス/ラベル自動割付
設定から ZR を外します**。外さないと、ZR のどのアドレスを書いても
「自動割付した範囲を超えている」で変換が止まります。ほかに RUN 中書込の
許可とラベルの取り込みが要ります。手順は
[doc/melsec.md](doc/melsec.md#事前設定-plc-1-台ごと) と、機種ごとの
`faruby_labels.md` にあります。

## 使い方

### プログラムの置き場

PLC で動かす mruby プログラムは `programs/` に置きます。**この中身は git の
管理外**なので、設備ごとのプログラムを置いたままにできます。

コンソールはここを探すので、**`compile` にはファイル名だけを書けば足ります**
(`compile blink.rb`)。パスで書けばそちらが優先されるので、別の場所に置いた
ものも扱えます。

### コンソールの起動

```bash
rake console
```

対話型コンソールが起動し、PLC との通信が可能になります。

### コンソールコマンド

| コマンド | 説明 |
|---------|------|
| `compile <file.rb>` | mruby としてコンパイル (`programs/` から探す) |
| `load` | バイトコードを PLC に転送 |
| `run` | VM 実行開始 |
| `instance [n]` | 操作対象のインスタンスを表示 / 切り替え |
| `status` | VM 状態を表示 |
| `regs [count]` | レジスタ値を表示 |
| `vars` | グローバル変数の値を表示 |
| `dev <device> [value]` | デバイスの読み書き (例: `dev DM100`, `dev DM100 42`) |
| `stop` | VM 停止 |
| `reset` | VM リセット要求を送信 |
| `verify` | PLC メモリとバイナリを比較 |
| `memmap` | メモリ配置を表示 |
| `disasm` | バイトコード逆アセンブル表示 |
| `sim` | PC 上のシミュレータで実行 |
| `connect` | PLC 接続確認 |
| `help` | コマンド一覧 |
| `quit` | 終了 |

### 使用例

```
faruby> compile test.rb
faruby> load
faruby> verify
faruby> run
faruby> status
faruby> regs
```

### エラーは 2 通りある

**どこで出るかで対処が変わります。**

| | いつ | PLC は | 見るところ |
|---|---|---|---|
| **コンパイル時** | `compile` / `load` | **動きません** (転送しない) | コンソールの `ERROR:` |
| **実行時** | `run` のあと | **ERROR で停止します** | `status` の `ERROR` と `PC` |

コンパイル時に出るのは書き間違いと容量超過です。デバイス名の間違い、割り付け
表の誤り、`FARUBY_` の書き間違い、バイトコードや変数が領域に収まらないとき。
**PLC には何も送られないので、設備は動きません。**

実行時に出るのは型と上限です。無いメソッドを呼んだ、レシーバの型が合わない、
呼び出しが深すぎる、プールを使い切った、など。**動いている途中で止まるので、
`status` で `ERROR` と `PC` を見てください。**

```
faruby> status
  STATUS   : 3 (エラー)
  PC       : 42
  ERROR    : 4
```

### 複数プログラムの並行実行

インスタンスごとに独立した VM が動き、それぞれ別のプログラムを実行します。

```
faruby[0]> compile a.rb
faruby[0]> load
faruby[0]> run
faruby[0]> instance 1
faruby[1]> compile b.rb
faruby[1]> load
faruby[1]> run
```

`compile` / `load` / `run` / `status` / `regs` はすべて選択中のインスタンスに
対して働きます。数は `faruby.yml` の `memory.instances` で決まり、変更したら
`rake vm_core` で再生成して取り込み直します。

### 電源を入れ直したとき

**実行中だったプログラムは先頭から走り直します。** 中断したところからは
続けません。設定は要らず、電源が切れたときの状態で決まります。

| 切れたときの状態 | 入れ直したあと |
|---------------|--------------|
| 実行中 | **先頭から走り直す** |
| 停止・完了・エラー | そのまま止まっている |

転送したプログラムもメソッドの定義も残るので、`load` し直す必要はありません。
初期化されるのは実行の位置と値を置く場所です。

| 初期化するもの | 残すもの |
|-------------|---------|
| 実行位置・状態・エラー・歩数 | 転送したプログラム (バイトコード) |
| レジスタ・呼び出しフレーム | メソッド表 (`load` が作るもの) |
| 配列プール・**汎用グローバル変数** | `$FARUBY_TICKS` |

`$timer1` のように覚えておいた値も消えるので、時間の起点は走り直した後に
取り直されます。**消えてほしくない値は
[デバイスに割り付けてください](#変数を実デバイスにする)。**

### グローバル変数による PLC デバイスの読み書き

`$` で始まる変数名がそのままデバイスを指します。

```ruby
$DM100 = 42          # DM100 に書き込み (16ビット符号付き)
$MR10 = 1            # ビットデバイスを ON
$total = $DM100 + 1  # デバイス名でない場合は汎用グローバル変数
```

### デバイスの割り付け

**設備が変わってもプログラムを直さずに済みます。** デバイスを抽象的な名前で
書き、実デバイスへの割り付けを別のファイルに持たせます。

プログラムの先頭 1 行でどの表を使うかを書きます。

```ruby
# devices: line1.devices.rb

$y0 = true if $x0        # 配線を知らなくても書ける
$DM100 = $speed
```

**装置分を並べておき、`##` で無効にして切り替えられます。** 行を消さずに
残せるので、どの装置の表があるかが一覧になります。

```ruby
# devices: line1.devices.rb      1 号ライン
## devices: line2.devices.rb     2 号ライン
## devices: line3.devices.rb     試験機
```

`#` の直後が `#` だと読みません。名前の後ろには覚書きを書けます。
**有効な行が 2 本あると `compile` がエラーになる**ので、`##` の付け忘れに
気づけます。全部無効にすれば割り付けなしに戻ります。

表は Ruby で書きます (`programs/line1.devices.rb`)。**これは PC 側で動く
ので、mruby の部分集合という制限はありません。**

```ruby
FaRuby.devices do
  map "x0",    "R0"       # 起動ボタン
  map "x1",    "MR102"    # 原点センサ
  map "y0",    "R500"     # コンベア
  map "speed", "DM300L"   # 幅も書ける
end
```

**読むときに Ruby として実行します。** 連番の配線を手で並べずに済みます。

```ruby
FaRuby.devices do
  16.times { |i| map "in_#{i}",  "R#{i}" }
  16.times { |i| map "out_#{i}", "R#{500 + i}" }
end
```

| | |
|---|---|
| **遅くなりません** | `$R0` と直に書いたのと同じ速さです |
| **表は任意** | 書かない設備も、**表に無い名前も今までどおり**実デバイスとして読みます。混ぜて書けます |
| 置き場所はプログラムの隣 | 1 つの表を複数のプログラムで共有することもできます |

`compile` が表を読み、何点読んだかを表示します。`dev` も割り付けた名前で
読み書きできます。

```
$ compile line1.rb
Compiling: programs/line1.rb
割り付け: programs/line1.devices.rb (4 点)
OK: nlocals=1, nregs=4, ilen=36, pool=0, syms=3

$ dev speed
speed = 1500
```

**幅は名前を引いてから付きます。** `$y0L` は表の `y0L` を先に探し、無ければ
`y0` を引いて `.L` を付けます。使う側に書いた幅が表のものより優先します。

**名前の書き間違いは `compile` がエラーにします。** PLC へは転送されません。

- 表のファイルが見つからない (`# devices:` 行の書き間違い)
- 同じ名前を 2 度割り付けた
- 割り付け先が読めない (`map "x0", "ZZZ9"`)。使っていない名前でもエラーです
- 実デバイスと重なる名前 (`map "DM100", "R0"`)。**使える名前は機種で違います**
  — 三菱には X / Y があるので `x0` は実デバイスです。両方で使う表には
  `in_0` のように区切りを入れた名前を選んでください
- 割り付け先と使い方が食い違う (`$x0T6` でビットデバイスに文字列)

#### 添字で引ける範囲

**ワード数を渡すと、連続した範囲になります。**

```ruby
FaRuby.devices do
  map "iai_regs", "D100", 8     # $iai_regs[0] が D100、[7] が D107
end
```

```ruby
8.times { |i| $iai_regs[i] = 0 }
$iai_regs[2] = 1500
```

`$DM[i]` は DM0 からですが、割り付けた名前なら**基点を設備に合わせられます**。
`compile` で読んだ表はコンソールからも見えます。

```
$ dev iai_regs
iai_regs = D100 から 8 ワード
  [0] D100 = 0
  [1] D101 = 0
  [2] D102 = 1500
  ...
```

| | |
|---|---|
| 数えるのはワード | 幅を付けても 1 つ飛びにはなりません。`map "pair", "D110L", 4` なら `$pair[0]` が D110-111、`$pair[2]` が D112-113 です |
| ビットデバイスも作れる | 番号はメーカーの数え方です。キーエンスの `MR110` は番号 26 なので、`$bits[6]` は `MR200` になります (チャンネルをまたぎます)。三菱の `M110` は 110 なので `M116` です |
| **範囲外は止まりません** | `$iai_regs[8]` は隣の D108 を書きます。**添字の範囲は自分で確かめてください** |

**ワード数を書かなければ今までどおり 1 点です。** そのとき添字は付けられません
— `$x0[i]` と書くと `x0` の値のビットを取り出す形になります。

全部を抽象化したい設備では表に `warn_unmapped!` を書くと、表を通らずに
実デバイスとして読んだ名前を `load` のときに知らせます。止めはしません。

```ruby
FaRuby.devices do
  warn_unmapped!
  map "x0", "R0"
end
```

#### 変数を実デバイスにする

**配線でない変数も割り付けられます。** 割り付けた名前はデバイスになるので、
値が PLC のデバイスに乗ります。

```ruby
FaRuby.devices do
  map "counter", "DM1050"   # もとは汎用グローバル変数
end
```

| 変わること | |
|---|---|
| `load` で消えない | 汎用グローバル変数は `load` でスロットを 0 に潰されますが、デバイスは残ります |
| インスタンスをまたいで共有できる | 汎用グローバル変数はインスタンスごとに別です |
| ラダーや表示器から見える | デバッグと運転表示に使えます |
| 変数の枠を使わない | `max_globals` (既定 100) の数に入りません |

デバイスの決まりがそのまま効きます。**配列も文字列も持てます。**

```ruby
$list  = [1, 2, 3]   # DM1060-1062 へ並ぶ
$name  = "abc"       # 文字で入る
$ratio = 1.5         # 0 方向へ切り捨てて 1
```

**`nil` は持てません。** デバイスは数値しか持てないので 0 になります。

```ruby
$once ||= 7          # ← 一度も代入されません
```

デバイスから読んだ 0 は Ruby では真なので、`||=` は働きません。初回だけの
処理は `nil` に頼らず、明示的な値で判断してください。

```ruby
$once = 7 if $once == 0
```

### 配列をまとめて書く

配列をデバイスへ代入すると、要素が連続したデバイスへ並びます。

```ruby
$DM100  = [11, 22, 33]   # DM100, DM101, DM102
$DM100L = [100, 200]     # DM100, DM102 (32 ビットは 2 ワードずつ)
$MRL[64] = [5, 6]        # 64, 96 ビット目 (ビットは 1 ワード = 16 ビット)
```

**刻みは幅で決まります。** 個別ビット (`$MR[64]`) には書けません。要素は
数値だけで、文字列や配列が混ざると**実行時エラーで停止します**。ハッシュも
書けません。

読む向きは個数を書きます。

```ruby
a = $DML[100, 3]   # DM100, DM102, DM104 の 3 個
```

Ruby の `a[i, n]` と同じで、**個数が負なら `nil`**、0 なら空の配列です。
容量 (12) を超える個数はエラーになります。**書く向きの `$DML[100, 3] = a`
はありません。** Ruby は範囲を置き換えて長さを変えますが、デバイスは長さが
固定なので同じ意味になりません。並べて書くだけなら `$DM100 = a` です。

**デバイス名でないグローバル変数は、どの型でも持てます。** 実数・配列・
ハッシュ・文字列・`true` / `false` / `nil` がそのまま入ります。

**同じ変数に違う型を入れ直してもかまいません。** ただし**入れ替えても元の
配列や文字列は回収されない**ので、ループの中で作り続けるとプールを
使い切ります。

アクセス幅を末尾で指定できます。既定は 16 ビット符号付きです。

| 表記 | 意味 | 占有 |
|------|------|------|
| `$DM100` / `$DM100S` | 16ビット符号付き (既定) | 1 ワード |
| `$DM100U` | 16ビット符号なし | 1 ワード |
| `$DM100L` | 32ビット符号付き | 2 ワード |
| `$DM100D` | 32ビット符号なし | 2 ワード |
| `$DM100F` | 単精度実数 | 2 ワード |
| `$DM100T6` | 6 バイトの固定長文字列 | 3 ワード |
| `$DM100T` | 終端付き文字列。**書き込み専用** | 中身次第 |

**`T` の数はバイト数です。** ASCII なら文字数と同じで、固定長の余りは
`FARUBY_STR_FILL` (既定は 0x00) で埋めます。読むときは桁が要ります —
`$DM100T` は長さが決まらないためエラーです。読んだ中身は何も落とさないので、
埋め物も文字列に入ります。

同じデバイスを異なる幅で参照すると領域が重なります。割り当ての管理は
プログラム作成者が行ってください。

**アンダースコアで区切ってもかまいません** (`$DM100_L`)。B は 16 進アドレスで
`D` と `F` が数字と重なるため、区切らないと `$B1F` は 0x1F と読まれます。
0x1 を実数で扱いたい場合は `$B1_F` と書きます。

**略記も使えます。** KV が受け付けるものと同じで、正式名に正規化されます。

| 略記 | 正式名 | デバイス |
|------|-------|---------|
| `$E100` | `$EM100` | 拡張データメモリ |
| `$D100` | `$DM100` | データメモリ |
| `$M100` | `$MR100` | 補助リレー |
| `$L100` | `$LR100` | ラッチリレー |

### ビットデバイスを整数として扱う

ビットデバイスに幅を付けると、そのビットから**連続したビット列**を整数として
読み書きします。チャンネル境界に揃っていなくてもかまいません。

```ruby
$MR[64] = true
$MR[65] = true
a = $MRL[64]      # 3 (下位2ビットが立つ)
$MRU[80] = 6      # MR501 と MR502 が ON
```

タイマとカウンタだけは意味が違い、幅を付けると**現在値**を返します
(`$T0D`)。幅によらず同じ値です。実数 (`$T0F`) は使えません。

**タイマとカウンタが使えるのは KV-5000 だけです。** KV-X500 では読み取りも
できません ([デバイス対応状況](doc/plc_devices.md#keyence-kv-シリーズ-kv-x500))。

### 実行時にアドレスを決める

`$DM100` のようにアドレスを書いた形はコンパイル時に確定します。実行時に計算した
アドレスへアクセスするには、アドレスを外して添字を付けます。

```ruby
i = 0
while i < 10
  $DM[600 + i] = 0
  i = i + 1
end
```

幅サフィックスも付けられます (`$DML[612]` は 32 ビット)。

**添字はデバイス番号です。** ワードデバイス (EM, DM, ZF) は表示上のアドレスと
一致しますが、MR / R / B は一致しません。MR400 は番号 64、B10 は 16 です。
番号空間では線形なので、MR415 の次は MR500 になります。

```ruby
$MR[64] = true    # MR400 を ON
```

ビットデバイスは `true` / `false` を返すので、そのまま条件に書けます。

```ruby
if $MR10
  $MR20 = true
end
```

ワードデバイスは整数です。Ruby では 0 も真なので、非ゼロ判定は
`if $DM100 != 0` と書いてください。

### faRuby が用意する名前

**`FARUBY_` で始まる名前は faRuby の予約です。** デバイス名でも利用者の変数
でもなく、faRuby 自身が中身を用意します。

| 名前 | 種類 | 型 | 内容 |
|------|------|-----|------|
| `$FARUBY_TICKS` | グローバル変数 | 整数 | 数え始めてからのミリ秒。**電源を入れ直しても 0 に戻りません** |
| `$FARUBY_CLOCK_10MS` | グローバル変数 | 真偽値 | 10ms クロックパルス |
| `$FARUBY_CLOCK_100MS` | グローバル変数 | 真偽値 | 100ms クロックパルス |
| `$FARUBY_CLOCK_1S` | グローバル変数 | 真偽値 | 1s クロックパルス |
| `FARUBY_STR_FILL` | 定数 | 整数 | 固定長でデバイスへ書いたときの余りを埋めるバイト (既定 0x00) |

**グローバル変数は読む側です。** 書いても次のスキャンで上書きされます。
**定数は書く側**で、`$` が付かず `FARUBY_STR_FILL = 0x20` のように代入して
設定します。

**表に無い `FARUBY_` の名前は `compile` がエラーにします。** 書き間違いが
そのまま動いてしまうことはありません。

```ruby
$FARUBY_TIKS          # → エラー。$FARUBY_TICKS の書き間違い
FARUBY_STRFILL = 0x20 # → エラー。FARUBY_STR_FILL の書き間違い
```

時間の使い方は下の「[時間](#時間)」に、`FARUBY_STR_FILL` は上の
アクセス幅の表 (`T` サフィックス) の説明にあります。

### 時間

**ラダーを書く必要はありません。** 上の 4 つのグローバル変数を読むだけです。

**止まって待つことはできません。** VM はスキャンごとにラダーへ戻るので、
`sleep` にあたるものがありません。時間は**差で判断します**。

```ruby
t0 = $FARUBY_TICKS
# ... 別の仕事 ...
if $FARUBY_TICKS - t0 >= 3000
  $MR100 = true      # 3 秒経った
end
```

**一周しても差は正しく出ます。** 32 ビット符号付きなので約 24.8 日で回り
込みますが、引き算がそのまま経過ミリ秒になります。またぐ瞬間を気にせず
書けます (差が 2^31 ミリ秒を超えるほど間を空けた場合は別です)。

クロックパルスは真偽値なので、そのまま条件にも代入にも使えます。

```ruby
$MR200 = $FARUBY_CLOCK_1S     # 1 秒周期で点滅する
$DM100 = 1 if $FARUBY_CLOCK_100MS
```

**刻みは 10ms です。スキャンタイムが 5ms を超えると時間が遅れます。**
`vm.steps_per_cycle` を大きくしすぎないでください。

クロックに使っているデバイス (KV は `CR2004` / `CR2005` / `CR2006`、MELSEC は
`SM409` / `SM410` / `SM412`) を**プログラムから直接読むことはできません。**
上のグローバル変数を使ってください。

### PLC 側 VM の取り込み

**メモリ配置やインスタンス数を変えたときだけ必要な手順です。** 既定のまま
使うなら、`plc/` に入っているプロジェクトを転送するだけで動きます。

```bash
rake vm_core
```

**全機種ぶんまとめて出します** (`plc/<メーカー>/<機種>/vm_*`)。生成された
ものを KV Studio や GX Works に取り込み、PLC へ転送します。**スクリプトは
複数に分かれ、ラダーが決まった順に呼びます。** 並べ方は
[doc/architecture.md](doc/architecture.md#スクリプトの分割とラダー-実機で確認済み)
にあります。生成物は直接編集しないでください。

取り込んだ後、ニーモニックを書き出して照合できます。

```bash
rake transfer
```

**PLC に入っている中身と生成物を 1 行ずつ比べ、取り込み直すファイルを挙げます。**
スクリプトは 13 本あるので、入れ替え忘れをここで見つけられます。

### 実行速度の計測

```bash
rake bench
```

**終わらないループを走らせ、`STEP_COUNT` の伸びを見ます。** 相手の選び方は
`rake hw` と同じで、`SECONDS` と `ROUNDS` で長さと回数を変えられます。

```
  ループ                命令/秒        1命令         スキャン周期       ばらつき
  OP_ADDI         258,959      3.9 µs        0.19 ms      0.1%
  OP_ADD          264,840      3.8 µs        0.19 ms      0.0%
```

周回数を `$DM660L` に置くので、ラダーが DM660-DM661 を使っていないことを
確かめてください。

## 現在の対応範囲

**mruby のうち、次が動きます。**

- 整数の四則演算、比較、代入
- [組み込みメソッド](#組み込みメソッド) 28 個
- メソッドの定義と呼び出し (`def`、引数・再帰・`return`)
- ブロック (`times` / `upto` / `each`、入れ子・`break`)
- 配列 (リテラル・添字・`length` / `size` / `<<` / `push` / `each`)
- ハッシュ (リテラル・添字・`length` / `key?` / `keys` / `values` / `each`)
- 文字列 (リテラル・デバイスとの読み書き・`==` / `+` / 式展開・
  `length` / `empty?` / `<<` / `[]`)
- `if` / `while` による分岐と繰り返し
- `nil` / `true` / `false` と整数の区別 (`if 0` は Ruby と同じく真)
- 実数 (単精度)。整数と混ざると Ruby と同じく実数になる
- グローバル変数と PLC デバイスの読み書き
- 実行時に決めたアドレスへのデバイスアクセス (`$DM[600 + i]`)
- 複数プログラムの並行実行 (既定 2 インスタンス)

整数は 32 ビット符号付き、実数は IEEE754 単精度です。

実数の 0 除算は Ruby と同じく `Infinity` を返しますが、**その値を演算に使うと
PLC が軽度エラーを出します**。0 除算が起こりうる箇所では除数を先に確かめて
ください。

**0 除算だけではありません。** `1.0e30 * 1.0e30` のように単精度の範囲を超える
計算も `Infinity` になり、その後の**比較が黙って違う答えを返します** (`b > 1.0`
が偽になる)。faRuby は検出しないので、範囲を超えうる計算は避けてください。
詳細は [doc/differences.md](doc/differences.md) の第 2 部にあります。

文字列はバイト列を変換しません。ソースの文字コードがそのままデバイスへ出ます。
詳細は [doc/string.md](doc/string.md)。

**Ruby として書いたつもりのものがどうなるかは
[doc/differences.md](doc/differences.md) の第 1 部にまとめてあります。**
止まらずに意味だけ変わるもの (大小比較が型を見ない、整数が 32 ビットで
一周する) が載っているので、書き始める前に一度目を通してください。

### メソッドの定義と呼び出し

```ruby
def clamp(v)
  return 0 if v < 0
  v * 2
end
$DM100 = clamp(3)
```

引数・再帰・途中の `return`・メソッド内からのデバイスアクセスが動きます。
**呼び出しの深さには上限があります** (`memory.max_frames`、既定 16)。
超えると実行時エラーで停止します。

省略可能引数 (`def f(a, b = 1)`)、可変長引数、キーワード引数は未対応です。

### ブロック

`times` / `upto` / `each` にブロックを渡せます。

```ruby
sum = 0
3.times do |i|
  sum = sum + i
end

1.upto(5) do |i|
  $DM[600 + i] = i
end

10.times do |i|
  break if $MR100
  $DM700 = i
end
```

入れ子、`break`、メソッドの中のブロック、ブロックの中からのメソッド呼び出しが
動きます。ブロックは外側のローカル変数を読み書きできます。

`yield` とブロック引数 (`&blk`) は未対応です。繰り返しは `while` と
`loop` が使えます。

```ruby
loop do
  # PLC の 1 サイクル
  break if $MR30     # break でしか終わらない
end
```

### 組み込みメソッド

次の 28 個です。**これ以外を呼ぶと実行時エラーで停止します。** レシーバの
型が合わないときも同じです (`5.length`)。

| メソッド | 引数 | レシーバ | 動作 |
|---------|------|---------|------|
| `!=` / `!` | 1 / 0 | すべて | `1 != 1.0` は偽、`nil != false` は真 |
| `%` | 1 | 整数 | 符号は除数に合う (`-7 % 3` は 2)。実数は未対応 |
| `abs` | 0 | 整数・実数 | 型は変わらない |
| `to_i` / `to_f` | 0 | 整数・実数 | `to_i` は 0 方向へ切り捨て |
| `floor` | 0 | 整数・実数 | −∞ 方向。`(-2.7).floor` は −3 |
| `round` | 0 | 整数・実数 | 0 から遠い方へ丸める。`2.5.round` は 3 |
| `-@` / `+@` | 0 | 整数・実数 | 単項の符号。`-x` と `+x` |
| `&` / `\|` / `^` | 1 | 整数 | ビットごとの積・和・排他的和。実数は不可 |
| `~` | 0 | 整数 | ビット反転。`~5` は −6 |
| `>>` | 1 | 整数 | 右シフト。負の値は符号を保つ (Ruby と同じ) |
| `times` | 0 | 整数 | 0 から n-1 まで。**ブロック必須** |
| `upto` | 1 | 整数 | a から b まで。**ブロック必須** |
| `length` / `size` | 0 | 文字列・配列・ハッシュ | **文字列は文字数** (`"あ".length` は 1)。ハッシュは組の数 |
| `empty?` | 0 | 文字列・配列・ハッシュ | 長さが 0 なら `true` |
| `<<` | 1 | 整数・文字列・配列 | 整数は左シフト。文字列は中身を継ぎ足し、配列は末尾に足す |
| `each` | 0 | 配列・ハッシュ | **ブロック必須。** 配列は要素、ハッシュは鍵と値を渡す |
| `push` | 1 | 配列 | 末尾に足してレシーバを返す (Ruby の String に `push` は無い) |
| `key?` | 1 | ハッシュ | 鍵があれば `true` |
| `keys` / `values` | 0 | ハッシュ | **新しい配列**を返す。プールを 1 スロット使う |
| `[]` | 2 | デバイス参照 | `$DML[100, 3]` で 3 個読んで**新しい配列**にする。1 スロット使う |
| `loop` | 0 | self | **ブロック必須。`break` でしか終わりません。** ブロックに値は渡しません |

`times` / `upto` / `each` / `loop` はブロック無しで呼ぶと実行時エラーです。

**ビット演算は 32 ビット符号付きで行います。** PLC のデバイスを扱うときに
使う形です。左シフトで桁があふれると一周します。

シフトの端も Ruby に合わせてあります。**桁数が負なら向きが逆**になり
(`5 << -1` は 2)、32 桁以上ずらすと**左は 0、右は符号で埋まります**
(`-5 >> 32` は −1)。

```ruby
$DM100 = $DM100 | 0x0004      # ビット 2 を立てる
$DM100 = $DM100 & ~0x0004     # ビット 2 を落とす
if $DM100[2] == 1             # ビット 2 を見る
  $MR10 = true
end
```

**整数に添字を付けるとビットが 1 つ取れます** (`Integer#[]`)。
`(n >> i) & 1` と書かずに済みます。添字が負なら 0、32 以上なら符号ビットで、
ここも Ruby と同じです。

```ruby
n = 5
n[0]      # 1
n[1]      # 0
n[31]     # 0   正の数の符号ビット
(-1)[40]  # 1   上は無限に符号が続く
```

書き込み (`n[0] = 1`) は Ruby にも無いので使えません。

**ワードデバイスのビットは読んで直して書きます。** ラダーの `DM0.0` に
当たるものは書けません。

```ruby
$DM100 |= 1 << 3      # ビット 3 を立てる
$DM100 &= ~(1 << 3)   # 落とす
$DM100[3]             # 読む

a = 100 + i
$DM[a] |= 1 << 3      # 添字でも同じ
$DM[a][3]
```

`1 << 3` はコンパイル時に 8 になるので、実行時のシフトはありません。
ビットデバイス (R / MR / B / LR) は PLC がビットで持っているので、
`$MR10 = true` や `$MR[64] = true` とそのまま書けます。

**`x[i] op= v` は配列とハッシュでも使えます。**

```ruby
a[0] += 5
h["n"] += 2
```

**配列・ハッシュ・文字列を作るとプールを消費します。** 回収しないので、
ループの中で作り続けると 16 個目で実行時エラーになります。`keys` /
`values` / `+` / `s[i]` も 1 つ作ります。詳細は
[doc/heap.md](doc/heap.md)。
