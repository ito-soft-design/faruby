# ロードマップ

何を作るかと、なぜその順序なのかの記録です。

## 現在できること

- 整数 (32ビット符号付き) と実数 (単精度) の四則演算・比較
- 整数のビット演算 (`&` `|` `^` `~` `<<` `>>`)
- `nil` / `true` / `false` と数値の区別。真偽判定は Ruby と同じ
- `if` / `while` による分岐と繰り返し
- グローバル変数と PLC デバイスの読み書き (アクセス幅の指定を含む)
- クラス (`class` / `new` / `initialize` / オブジェクトごとの `@foo` /
  クラスごとの `@@foo`)。継承は未対応
- 定数 (`FOO = 1`)。`C::LIMIT` の形は未対応
- 組み込みメソッド 29 個。一覧は [README](../README.md#組み込みメソッド)
- メソッドの定義と呼び出し (引数・再帰・途中の `return`・`obj.foo`)
- ブロックと反復 (`times` / `upto` / `each` / `break` / `loop`)
- 配列 (リテラル・添字・`length` / `size` / `<<` / `push` / `each`)
- ハッシュ (リテラル・添字・`length` / `key?` / `keys` / `values` / `each`)
- 文字列 (リテラル・デバイスとの読み書き・`==` / `+` / 式展開・
  `length` / `empty?` / `<<` / `[]`)
- 単項の符号 (`-x` / `+x`)
- 時間 (`$FARUBY_TICKS` と 3 つのクロックパルス。ラダーは要らない)
- 複数プログラムの並行実行

**4 機種で動きます** — KV-5000 / KV-X500 / MELSEC Q / MELSEC iQ-R。
実機で一致した値は 260 / 258 / **104** / 258 です。**Q が少ないのは
文字列・配列・ハッシュを載せていないから**で、VM の違いではありません
([doc/melsec.md](melsec.md))。

実装済みの命令は 67 個です。詳細は [対応オペコード一覧](opcodes.md)。

**ロードマップの項目はすべて片付きました。** 残っているのは
[独立した項目](#独立した項目) と、文字列の加工 (`*` / `sub` / 書式化) です。

## 依存関係

```
動的デバイスアクセス ── 独立。ヒープもメソッドも不要
組み込みメソッド ────── OP_SEND の限定実装。呼び出しフレーム不要
メソッド定義・呼び出し ── 子 irep + 呼び出しフレーム
        │
      ブロック ──────── each / times / upto
        │
   ヒープ設計 ────── Array ── Hash ── String
                                    ↑ ここまで実装済み
```

## なぜ Array / String / Hash が先ではないのか

**リテラルと添字以外はすべてメソッド呼び出しだからです。** 逆アセンブルで
確認した結果です。

```
[1, 2, 3]      → OP_ARRAY2     専用命令
e[0]           → OP_GETIDX     専用命令
"hi"           → OP_STRING     専用命令
a.length       → OP_SEND       メソッド呼び出し
a.push(4)      → OP_SEND
a.each { }     → OP_BLOCK + OP_SENDB
```

Array を入れても、作って添字で読むだけで `length` も `push` も `each` も
動きません。メソッド呼び出しとヒープの両方が揃って初めて実用になります。

## 1. 動的デバイスアクセス — 実装済み

デバイスアドレスがコンパイル時に確定するため、実行時に計算したアドレスの
デバイスを読み書きできませんでした。センサ群やレシピデータをまとめて扱う、
PLC ではごく普通の処理ができない状態でした。

```ruby
i = 0
while i < 10
  $DM[600 + i] = 0
  i = i + 1
end
```

アドレスを外した `$DM` を「デバイス族」とし、添字を付けて実行時に決めます。
`OP_GETIDX` / `OP_SETIDX` は専用命令なのでメソッド呼び出しもヒープも不要でした。

決めた内容は [デバイス参照](architecture.md#デバイス参照-tt_device) にあります。

- 幅サフィックスは `$DML[i]`。正式名を略記より先に解析するため一意に決まる
- `$DM100[i]` は不可。`$DM100` はスカラとしても使われ、どちらも同じ
  `OP_GETGV` になるため VM 側で区別できない
- 範囲チェックあり。EM は範囲外を読むと 512 ワード周期で値が返るため
- 添字はデバイス番号。MR400 は 64。`plc_access` の `PlcDevice` と同じ規則

## 2. 組み込みメソッド — 実装済み

`a != b` が書けませんでした。`OP_SEND` にコンパイルされるためです
(`if a == b` の else で代用していました)。`!` / `%` と
`abs` / `to_i` / `to_f` / `floor` / `round` も同じです。利用者が最初に
つまずくのはおそらくここでした。

逆アセンブルで確認した形です。

```
a != b     → OP_SEND [4, sym(!=), 1]     引数1個
!a         → OP_SEND [3, sym(!),  0]     引数なし
a % b      → OP_SEND [4, sym(%),  1]
a.abs      → OP_SEND [3, sym(abs), 0]
3.times {} → OP_BLOCK + OP_SENDB          ← 子 irep が要る。項目 4
```

`7 % 3` のような定数どうしは mrbc が畳み込むため `OP_SEND` になりません。
変数を挟んだときだけ現れます。

受け手の型とメソッド名の組み合わせを限定して `OP_SEND` を実装しました。
呼び出しフレームは作りません。引数は `R[a+1]` から連続して並び、結果は
`R[a]` に返るためです。

メソッド名はシンボル表にあり、シンボル表は既にデバイスマッピングテーブルの
索引として転送していました。**ホスト側で名前を小さな整数に解決して渡すため、
VM は文字列比較をせず整数の分岐だけで済みます。** シンボル表の 4 ワード目を
「デバイス族フラグ」から「シンボル種別」に広げ、メソッド名のエントリでは
1 ワード目にメソッド番号、3 ワード目に引数の数を入れています。メモリ配置は
変わっていません。

未対応のメソッドはコンパイル時ではなく実行時に `ERROR` で止まります
(受け手の型が実行時にしか分からないため)。

- 数値レシーバを要求するメソッドを連続した番号に並べ、型検査を 1 比較に
  収めている (真偽判定のタグ順と同じ手)
- `%` は整数どうしのみ。実数は型エラー
- `&` / `|` / `^` / `~` / `<<` / `>>` は後から入れた。`<<` は整数なら
  左シフト、文字列と配列なら継ぎ足し (Ruby と同じ)

実機で確認済みです ([test_18_methods.rb](../test/ruby_programs/test_18_methods.rb))。
シミュレータでは再現できない次の 2 つも通っています。

- 整数と実数の混在比較 (`EM16.L:Z9 <> EM1.F:Z1`)。`floor` の端数判定に使う
- 実数リテラルを含む式 (`EM1.F:Z1 + 0.5`)。`round` に使う

### エラーコード

| code | 意味 |
|------|------|
| 1 | 0 除算 (`/` と `%`) |
| 2 | 添字アクセス (デバイス参照でも配列でもない、または範囲外) |
| 3 | 未対応のメソッド、または引数の数が合わない |
| 4 | レシーバまたは引数の型が扱えない |
| 5 | 呼び出しが深すぎる (フレームまたはレジスタが足りない) |
| 6 | 引数の数または形が扱えない (省略可能・可変長・キーワードは未対応) |
| 7 | `OP_METHOD` / `OP_BLOCK` が指す子 irep が無い |
| 8 | 上位の変数に届かない (指定された段数だけ遡れなかった) |
| 9 | ブロックの扱いが不正 (ブロックでない値を渡した、反復の外で `break` した) |
| 10 | 配列の領域が足りない (プールを使い切った、要素数が容量を超えた) |

## 3. メソッド定義・呼び出し — 実装済み

設計と実装の記録は [メソッド定義・呼び出しの計画](method_calls.md) にあります。

`def` が書けます。引数・再帰・途中の `return`・メソッド内からのデバイス
アクセス・レシーバを書く呼び出し (`obj.foo`) が動きます。省略可能引数・
可変長引数・キーワード引数は未対応です。

**`obj.foo` は `OP_SSEND` の重複を消したときに動くようになりました。**
self をレシーバ位置に置いてから `OP_SEND` へ落ちる形にすると、どちらも同じ
経路を通ります (mruby と同じ)。組み込みメソッドの振り分けが 2 度展開されて
いたのも同時に消え、KV は 16% 縮みました。

呼び出しの深さは `memory.max_frames` (既定 16) とレジスタ領域で決まり、
超えるとエラーで停止します。PLC はメモリが固定なので、上限で止めるしか
ありません。

`def` は `OP_TCLASS` + `OP_METHOD` + `OP_DEF` で、**子 irep** を必要とします。
以前 `plc_codegen` はトップレベルの irep しか転送していなかったため、仕組みごと
未対応でした。入れたもの:

- 子 irep の転送とアドレス付け (IREP テーブル)
- 呼び出しフレーム (戻り先 PC・irep・レジスタ基点の退避)
- `OP_SSEND` (レシーバを書かない呼び出しはこちらになる)
- `OP_ENTER` (引数の数の検査)
- `OP_RETURN` のフレーム復帰
- メソッド表 (ホスト側で振った ID → irep)

工数の大半は**メモリ配置の作り直し**でした。バイトコード・定数プール・シンボル表
が irep ごとになり、生成コードで定数だったアドレスが VM 状態経由の間接参照に
変わりました。

## 4. ブロック — 実装済み

設計と実装の記録は [ブロックの計画](blocks.md) にあります。

`times` と `upto` にブロックを渡せます。入れ子・`break`・メソッドの中・
ブロックの中からのメソッド呼び出しが動きます。

```ruby
sum = 0
3.times do |i|
  sum = sum + i
end
```

`OP_SENDB` は呼び出しの仕組みでしかなく、**繰り返すのは `Integer#times` の側**
です。VM は再帰できないため、反復フレームに「今何回目か」と「上限」を持たせ、
ブロックの `OP_RETURN` で次の回に入り直します。

実機で確認済みです ([test_20_blocks.rb](../test/ruby_programs/test_20_blocks.rb))。
実行速度は 32,449 命令/秒、スキャン周期 1.54 ms です。

`loop` も入りました。`OP_SSENDB` (self への呼び出し) で `OP_SENDB` とは
別命令なので、self をレシーバ位置に置く前処理として足しています。
`yield` とブロック引数 (`&blk`) は未対応です。
`each` は Array と一緒に項目 5 で入りました。

## 5. ヒープ設計

設計メモは [ヒープの計画](heap.md) にあります。

Array / String / Hash に共通する置き場所です。固定数のスロットを持つプールを
用意し、**順に渡して返さない (GC 無し)、使い切ったらエラー**から始めます。

GC が難しいのは停止時間が読めないからですが、faRuby は**ヒープが固定長で根も
小さい**ため、必要になれば上限の計算できるマークスイープを後から足せます。
案 2 (エラー) と案 3 (回収) の間に Ruby としての意味の違いは無く、エラーが
出なくなるだけです。

逆アセンブルの結果、**既存の仕組みにかなり載る**ことが分かりました。
`OP_GETIDX` / `OP_SETIDX` は実装済みで枝を足すだけ、`length` / `<<` / `push`
は `OP_SEND`、`each` は `OP_SENDB` です。新しく要るのは `OP_ARRAY` /
`OP_ARRAY2` と実体の置き場所です。

リテラル・添字・`length` / `size` / `<<` / `push` / `each` が動きます。
実機で確認済みです
([test_21_arrays.rb](../test/ruby_programs/test_21_arrays.rb))。
実行速度は 32,711 命令/秒、スキャン周期 1.53 ms で、配列を入れる前から
変わっていません。

```ruby
a = [11, 22, 33]
$DM100 = a[1]     # 22
a[1] = 99

s = 0
a.each do |v|
  s = s + v
end
```

## 6. Array / String / Hash

3 つとも実装済みです。実体は共通の配列プールに置き、返さないので
使い切ったら止まります。詳細は [ヒープの設計](heap.md)、
[ハッシュの計画](hash.md)、[文字列の計画](string.md)。

String は**バイト列を変換しません**。ソースの文字コードがそのまま
デバイスへ出ます。種別を 1 ワード覚えておき、`length` と `[]` を
文字単位にしています。

```ruby
FARUBY_STR_FILL = 0x20    # 固定長の余りを空白で埋める

s = "あいう"
$DM100 = s                # 終端付き
$DM200T10 = s             # 10 バイトの固定長
$DM300 = s.length         # 3。バイト数の 9 ではない
$DM400 = s[0]             # "あ"
```

残るのは `*` (繰り返し) と `sub` / `upcase` などの加工、書式化です。
どれも新しいスロットを取るので、使う場面を見てから決めます。

## 独立した項目

| 項目 | 内容 |
|------|------|
| インスタンスを増やす | `memory.instances` を増やして EM20000-EM39999 を使い切る。1 インスタンス 4000 ワードなので 5 個まで。設定変更と再取り込みのみでコード変更は不要。**三菱は固定領域が ZR 8K しかないので 1 つだけ** |
| ~~Symbol~~ | 実装済み。値はホストが名前ごとに振った通し番号で、irep をまたいでも `==` で比べられる。Hash のキーに使う。詳細は [ハッシュの計画](hash.md) |
| ~~STEP_COUNT~~ | 実装済み。VM の最初のコミットから領域と `status` の表示はあったが、生成コードが更新しておらず常に 0 だった。`INC` で数えるようにした。費用は 1.5% |
| ~~固定領域を ZF へ~~ | 実装済み。実行中に変わらない領域を ZF のバンク 3 に移し、EM 側は 1 インスタンス 1000 ワードになった。当初は `FRSET` でバンクを選んで FM で指していたが、**バンクの先頭を基点にした相対指定**に変えた。詳細は [アーキテクチャ](architecture.md#固定領域はバンクの先頭からの相対で指す) |
| ~~実数のオーバーフロー検査~~ | **入れないと決めた。** 検出はできる (上位ワードの指数部を整数として見る) が、実数演算のたびに走る割に実数を使うプログラムが多くないため。利用者が避ける前提。測定結果と理由は [Ruby との違い](differences.md#検査を入れないと決めた) |
| ~~MELSEC 対応~~ | 実装済み。Q と iQ-R で 223 個ずつ実機一致。ST 1 本にまとまるのでラダーが要らない。実機で分かったことは [MELSEC 対応の計画](melsec.md) |
| mruby 4.0 対応 | オペコード番号の変更に追従。影響は `MRUBY_OPCODES` のみ |
| ~~PLC 起動時に先頭から実行する~~ | 実装済み。**走らせ直すかどうかは電源が切れたときの状態で決める** — 実行中だったら先頭から、停止・完了・エラーならそのまま止めておく。設定を足さなかったのは、これが利用者の意図とふつう一致するから。起動の合図は初回スキャンのみ ON の接点 (KV は CR2008、MELSEC は SM402。**4 機種すべて実機で確認済み** — 実行中のまま切ると走り出した回数が 1 増え、停止してから切ると増えない)。初期化するのは実行位置・状態・エラー・歩数・レジスタ・フレーム・配列プール・汎用グローバル変数で、**メソッド表とバイトコードは残す** (`load` し直さずに済む)。初期化はリセット要求と同じ処理を呼ぶ。**リセット要求に乗せる形は採らなかった** — 要求の枝は STATUS を停止にするので、「初期化のあと実行中へ戻す」ことを覚えておく語が VM 状態に 1 つ要る。初期化を 2 回展開する代わりに語を増やさずに済ませた (初期化はスキャンごとの経路ではないので費用は無視できる)。**電源が切れる前のリセット要求は落とす** — 残すと走らせ直した直後に止めてしまう。**三菱は可変領域が保持されていないと働かない** — 走り直す判断は `STATUS = 1` だが、`STATUS` も メソッド表も可変領域 (D) にあり、**三菱の D は既定で残らない**。保持していない Q で電源を入れ直したら `STATUS` も `NUM_IREPS` も 0、`$FARUBY_TICKS` は電源投入からの 127 秒だった (固定領域 ZR のバイトコードは残っていた)。キーエンスの EM は既定で残るので、4 機種で確認できていたのは三菱側が保持の対象になっていた間だけ。使い方は [README](../README.md#電源を入れ直したとき) |
| ~~時間を測る (tick カウンタ)~~ | 実装済み。`$FARUBY_TICKS` が数え始めてからのミリ秒 (**電源を入れ直しても 0 に戻らない**。EM / D に残る値から続ける。実機で確認)、`$FARUBY_CLOCK_10MS` / `_100MS` / `_1S` がクロックパルスそのもの。生成スクリプトが 10ms クロックの立ち上がりをスキャンごとに数える。**読み出しに枝を足していない** — ticks は普通のデバイス読み (32 ビット)、パルスは値スロットなので汎用グローバルの経路に載る。パルスを 1 / 0 の整数にしなかったのは Ruby では 0 も真だから。時刻源は機種が持つ (KV は CR2004/2005/2006、MELSEC は SM409/410/412。**4 機種すべて実機で確認済み**)。**値スロットはブロック先頭から 4 の倍数に置く** — 三菱は `VMSLOT[添字]` で指し、添字を「ワード数 / 4」で求めるためで、ずれると手前のスロットを読む (実機で起きた)。**スキャンタイムが 5ms を超えると取りこぼす。** 使い方は [README](../README.md#時間) |

## 次に考えること

**オブジェクト。** インスタンス変数 (`@`) は入りました
([インスタンス変数の計画](instance_vars.md))。残っているのはクラスです。

1 本でした。**`Counter.new(5).value` が動きます。** 残っているのはクラス変数

**固定メモリに何をどれだけ置くかの判断になります。** `TT_OBJECT` は今は
印だけで中身がありません。クラスごとのインスタンス変数の並び、インスタンスの
領域の上限、メソッド探索 (今はシンボル表のメソッド番号で直に振り分けている)
をどうするかが決まっていません。

**`@` の側は作り替えになります。** いまは「self が 1 つしか無い」ので名前
ごとに 1 枠ですが、`Foo.new` が 2 つできた時点で「どの self のものか」で
行き先が変わります。直すのは `OP_GETIV` / `OP_SETIV` の 2 命令と、シンボル
表の項目の意味だけです。

## 4. クラス変数と定数 — 実装済み

**まとめて入れました** (2026-11-26)。置き場を新しく作らずに済みました。

**どちらも汎用グローバルの値スロットです。** `$foo` と同じ場所なので、
VM に足したのは前処理 2 つ (`OP_GETCV` / `OP_SETCV` が `OP_GETGV` /
`OP_SETGV` の枝へ落ちる。`OP_GETIV` と同じ形) と、`OP_GETCONST` /
`OP_SETCONST` の種別による振り分けだけです。**領域は 1 ワードも増えません。**

| | 枠の鍵 | 行き先 |
|---|---|---|
| `$foo` / `@foo` (トップレベル) | 名前 | 汎用グローバル |
| `@@n` | **クラス番号 + 名前** | 汎用グローバル |
| `FOO` | 名前 | 汎用グローバル |
| `FARUBY_*` | — | VM 状態 (従来) |

**クラス変数の鍵にクラス番号を付けるのが要点です。** `@@n` の場所は名前では
なく「どのクラスの `@@n` か」で決まります。継承が無いので遡る探索は要らず、
**インスタンス変数より簡単**でした (あちらはオブジェクトごとに場所が違う)。

### 直した不具合 — 定数が黙ってクラス番号を返していた

`class_numbers` がクラス名を `OP_CLASS` と **`OP_GETCONST` の両方**から
集めていました。定数の読みも `OP_GETCONST` なので、**`FOO = 7` の `FOO` が
クラスとして登録され、`$DM0 = FOO` が 7 ではなく 1 を書いて完了していました**
(エラーも出ません)。クラス名は `OP_CLASS` だけから集めます — faRuby に
クラスを外から持ち込む経路は無く、必ず同じプログラムの `class X` で
定義されるためです。

**i8080 も同じ間違いをしていました。** 両方直しました。

### 止めるもの

**トップレベルの `@@n`** はコンパイル時に止めます。Ruby は 3.0 以降エラーに
しますが mruby は通すので、通すと faRuby でだけ動くプログラムが書けます。

**`C::LIMIT` の形**も止めます。`OP_GETMCNST` / `OP_SETMCNST` は未実装で、
**以前は実行時の「未知のオペコード 31」でしか分かりませんでした。** 定数は
名前を 1 つの空間で分け合うので、2 つのクラスが同じ名前の定数を持つと同じ枠
になります。入れ子を支える仕組み (どのクラスの名前空間か) は持っていません。

**再代入は通します。** Ruby は警告しますが、見分けるには「もう書いたか」を
覚える場所が定数 1 つにつき要ります。警告を出せないので止めるか通すかの
どちらかで、通す方を採りました。

確かめ方は test/test_constants.rb (15 本) と
test/test_i8080_constants.rb (6 本) です。

### 実機で確認したこと (KV-5000)

**286 値すべて一致** (前回 260 から +26)。`test_46_constants.rb` の 10 値が
新規で、期待値はシミュレータで先に突き合わせてあります。

**最初の実機で 3 本落ちました。** `test_44_classes` / `test_45_gc` /
`test_46_constants` が揃って `ERROR=3` です。**定数を足したつもりで、
既存のクラス参照まで壊していました。**

```
Z1 = ZF98304:Z7   ' シンボル種別      ← 種別を Z1 に読む
Z1 = EM7:Z9 * 4 + EM32:Z9 + Z9        ← 同じ Z1 をアドレスで潰す
IF Z1 = 6 THEN                        ← 種別ではなくアドレスを比べている
```

`reg_slot` はレジスタのアドレスを **Z1** に置きます。`device_table_lookup`
が種別を Z1 に入れた直後に呼んだためです。`OP_GETGV` が同じ形で無事なのは
`global_reg_slot` (Z2 を使う) を呼んでいるからで、そちらに合わせました。

**シミュレータでは絶対に出ません。** インデックスレジスタが無いので、
「どの Z に何が載っているか」という問題が存在しません。916 本が緑のまま
実機で全滅する形でした。同じ形を次に捕まえるテストを
test_kvs_generator.rb に入れてあります (種別を読んだ行と比較の間に Z1 への
代入があれば落ちる。わざと戻すと 2 箇所を行番号付きで名指しします)。

**直った生成物は 1 ファイルだけでした** (`vm_08_group4.kvs`)。
`OP_GETCONST` と `OP_SETCONST` が同じ組に入っているためです。

### 実機で確認したこと (4 機種)

| 機種 | 値 | 照合 | `test_46` |
|---|---|---|---|
| KV-5000 | **286** | 13 本一致 | 10 個 |
| KV-X500 | **284** | 13 本一致 | 10 個 |
| iQ-R | **284** | (MELSEC に照合は無い) | 10 個 |

KV-X500 が 2 値少ないのはタイマ・カウンタの試験が KV-5000 専用だからです。
Q が大きく少ないのは配列・文字列・ハッシュを外しているためで、
その 3 つを使う試験がまとめて飛びます (回収の試験もその中です)。

**KV-X500 では 13 本のうち 7 本が入れ替わりました** (KV-5000 は 1 本)。
中身が変わったのは 2 本だけで、残り 5 本は**前処理 2 つが命令の組の境目を
動かしたため、命令がファイル間を移動した**ものです。移動を伴う取り込みは
部分的にやると静かに壊れるので、照合が 13 本全部を見ているのが効きます。

**MELSEC は 1 ファイル (`vm_02_body.st`) で、照合がありません。** 取り込み
漏れは `rake hw` の結果でしか分かりません。

`test_46_constants_melsec.rb` はキーエンス版からデバイス名を置き換えた
ものです。**4 機種すべてで同じ 10 値を確認しました** — 定数とクラス変数は
配列・文字列・ハッシュに触らないので、Q で外している 3 つの型と無関係です。
**回収のときは Q だけ走らせられませんでした。** 機能によって確認できる
機種が変わるので、どの機種で何を見たかは機能ごとに書いています。

### 実機で確認したこと (ND8080)

**10 値すべて一致** (`STATUS=2` / `ERROR=0`)。PLC 4 機種と合わせて
**5 機種で確認できた**ことになります。

**値は 101-110 にしました。** 読み戻しは値で突き合わせるので、小さい数だと
偶然その場にある値と区別が付きません。この範囲なら、定数がクラス番号を
返す不具合 (直した不具合そのもの) なら 1-5 が出るので見分けられます。

結果はグローバル変数 `$g1`-`$g10` に入れて、走り終わってから
`ND8080::Remote#save` でグローバル領域 (0x9000-) を読み戻します。
**前の走行の残りではないと言えます。** 書き込みが同じ領域を nil スロットで
埋めてから (照合 OK) 走らせているためです。

**名前とアドレスの対応はシンボル表から作り直します。** グローバルの枠は
出てきた順に割り当てられるので、番号を決め打ちできません。生成した HEX の
シンボル表を irep の順に 2 バイトずつ読めば `$g1` の居場所が出ます。

```ruby
FOO = 101
A = 102
B = 103

class Holder
  INNER = 104
  def inner
    INNER
  end
end

# クラス変数はオブジェクトをまたいで 1 つ
class Counter
  def add(v)
    @@n = (@@n || 0) + v
  end
end

# インスタンス変数とクラス変数の取り違えを見る
class Both
  def setup
    @@c = 106
    @v = 108
    @@c
  end

  def vv
    @v
  end
end

# クラスが違えば別の @@n
class X
  def m
    @@n = 109
    @@n
  end
end

class Y
  def m
    @@n = 110
    @@n
  end
end

$g1 = FOO
$g2 = A
$g3 = B
$g4 = Holder.new.inner

Counter.new.add(50)
$g5 = Counter.new.add(55)   # 共有されていれば 105、別々なら 55

b = Both.new
$g6 = b.setup
$g7 = b.vv

$g8 = X.new.m
$g9 = Y.new.m
$g10 = X.new.m              # Y が X の @@n を潰していなければ 109
```

`programs/` は利用者の置き場 (`.gitignore` 済み) なので、プログラムは
ここに書いておきます。**定数プールの領域は書き込まれません** — 小さい整数
だけなのでプールのエントリが 1 つも無く、`rake i8080:upload` の領域一覧にも
0x7000 が出ません。

**ROM モードから入りました。** `rake i8080:upload` が自前で見分けて
`bank_init.hex` を流し、拡張 RAM に複製してから書き込みます。

**アセンブルは PowerShell から回します。** asm80 は npm のグローバル置き場に
あり、Bash からは見えません (status 127)。

## 当面やらないこと

**例外 (`begin` / `rescue`)。** faRuby に例外機構はありません。0 除算などは
VM の `ERROR` に code を書いて停止します。PLC のプログラムで例外による制御が
必要になる場面は考えにくく、優先度は低いままです。
