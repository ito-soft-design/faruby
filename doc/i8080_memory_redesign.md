# i8080 メモリ配置の再設計

拡張 RAM (62256) により 0x0000-0x7FFF が RAM として使えるようになったため、
メモリ配置を再設計する。

## 現在の配置 (RAM: 0x8000-0xFFFF のみ)

VM コードが 3KB 領域に収まらず、3 ブロックに分散している。

```

─────────────────────────────────────────────────────────────────────

0x8300-0x83C6   シンボルテーブル          198B     61B              31%
0x83C7-0x83F7   === 割り込みベクタ ===    49B      -                -
0x83F8-0x83FF   (空き)                    8B      -                -
0x8400-0x8FFF   VM コード (本体)        3,072B   3,034B           99% ← 限界
0x9000-0x9FFF   mruby バイトコード      4,096B     613B           15%

### 問題点

1. **VM コードが限界**: 本体 3,034/3,072 バイトで残り 38 バイト。新機能追加不可
2. **コード分散**: VM コードが 3 ブロックに分かれ、JMP でつないでいる
3. **バイトコード/定数プールの無駄**: flip_flop で 15%/3% しか使っていない
4. **空き領域が活用不能**: 0xB8F3-0xEFFF に 14KB 空いているが VM コードは届かない

### 使用量まとめ

| 領域 | VM コード | バイトコード | 定数プール | ランタイムデータ | 空き |
|------|----------|-------------|-----------|----------------|------|
| バイト数 | 6,049 | 613 | 66 | 1,568 | 17,320 |


## 新配置案 (RAM: 0x0000-0xFFFF 全域)

ROM を拡張 RAM にクローン済みの状態を前提とする。
VM コードを下位アドレスに移動し、連続した大きな領域を確保する。

```
アドレス          用途                    確保      備考
─────────────────────────────────────────────────────────────────────
0x0000-0x07FF   ND80Z モニタ ROM クローン  2KB     (bank_init が KEY パッチ済み)
0x0800-0x0FFF   (モニタ予約)             2KB      (触らない)
─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─
0x1000-0x4FFF   VM コード               16KB     連続領域 (現在の 2.6 倍)
0x5000-0x6FFF   mruby バイトコード        8KB     現在の 2 倍
0x7000-0x7FFF   定数プール               4KB     現在の 2 倍
─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─
0x8000-0x80FF   VM 状態                 256B     変更なし
0x8100-0x81FF   レジスタファイル          256B     変更なし
0x8200-0x82FF   IREP テーブル            256B     変更なし
0x8300-0x83C6   シンボルテーブル          198B     変更なし
0x83C7-0x83F7   === 割り込みベクタ ===    49B
0x83F8-0x83FF   (空き)                    8B
0x8400-0x8409   VM 起動スタブ             10B     SP設定 + OUT 9C,F8h → JMP vm_start
0x840A-0x8FFF   (空き)                3,062B
─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─
0x9000-0x90FF   グローバル変数            256B     移動 (0xB000→)
0x9100-0x91BF   フレームスタック          192B     ×2 (8→16 フレーム)
0x91C0-0x92BF   メソッド表               256B     ×2 (4→8 クラス)
0x92C0-0x96BF   オブジェクトプール      1,024B     ×4 (8→32 オブジェクト)
0x96C0-0x9FFF   コレクションプール      2,368B     ×4 (16→64 スロット)
─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─
0xA000-0xEFFF   (空き)              20,480B
0xF000-0xFDFF   CPU スタック           3,584B     変更なし
0xFE00-0xFFB7   (空き)                  440B

### 現在 → 新配置の比較

| 領域               | 現在         | 新配置        | 倍率 |
|--------------------|-------------|--------------|------|
| VM コード           | 6,049B (分散) | 16,384B (連続) | ×2.7 |
| バイトコード         | 4,096B      | 8,192B       | ×2   |
| 定数プール           | 2,048B      | 4,096B       | ×2   |
| フレームスタック      | 96B (8枠)   | 192B (16枠)   | ×2   |
| メソッド表           | 128B (4cls) | 256B (8cls)   | ×2   |
| オブジェクトプール    | 256B (8個)  | 1,024B (32個)  | ×4   |
| コレクションプール    | 576B (16枠) | 2,368B (64枠)  | ×4   |

### 利点

1. **VM コード 16KB**: 連続領域で分散解消、今後の機能追加に余裕
2. **バイトコード 8KB / 定数プール 4KB**: より大きなプログラムに対応
3. **コレクション ×4**: 文字列・配列・Hash が 64 スロット使える
4. **オブジェクト ×4**: 32 インスタンスまで生成可能
5. **フレーム ×2**: ブロックのネストが 16 段まで
6. **クラス ×2**: ユーザー定義クラスが 7 個まで

### 起動シーケンス

VM コード本体は 0x1000 (拡張 RAM 領域) にあるため、起動時はまず
0x8400 の起動スタブでバンクを切り替えてから JMP する。

```
0x8400 (通常 RAM — 常にアクセス可能):
  lxi sp, STACK_TOP + 1
  mvi a, 0F8h
  out 9Ch           ; 拡張 RAM バンク選択
  jmp vm_start      ; → 0x1000 へ
```

bank_init (ROM クローン + KEY パッチ) は hex ロード前に別途実行される。
bank_init も org 0x8400 だが、hex ロード時に起動スタブで上書きされる。
upload 時の実行アドレスは従来通り 0x8400。

### 変更が必要なもの

- `VM_CODE_ORG`: 0x8400 → 0x1000
- `BYTECODE_BASE`: 0x9000 → 0x5000
- `BYTECODE_SIZE`: 0x1000 → 0x2000
- `POOL_BASE`: 0xA000 → 0x7000
- `POOL_SIZE`: 0x0800 → 0x1000
- `GLOBALS_BASE`: 0xB000 → 0x9000
- `FRAME_STACK_BASE`: 0xB100 → 0x9100
- `MAX_FRAMES`: 8 → 16
- `METHOD_TABLE_BASE`: 0xB160 → 0x91C0
- `MAX_CLASSES`: 4 → 8
- `OBJECT_POOL_BASE`: 0xB1E0 → 0x92C0
- `MAX_OBJECTS`: 8 → 32
- `COLLECTION_POOL_BASE`: 0xB2E0 → 0x96C0
- `MAX_COL_SLOTS`: 16 → 64
- `vm_main.a80`: 起動スタブを org 0x8400 に配置、本体を org 0x1000 に移動
- `bank_init.a80`: KEY ルーチンの OUT 9C 値をパッチ (bit3=1 維持)
- `Rakefile`: 実行アドレスは 0x8400 のまま
- `i8080_board.rb`: テスト側の VM_CODE_ORG 参照
- `i8080_bytecode_hex.rb`: バイトコード/プール配置アドレス変更

### 注意事項

- 0x0000-0x0FFF はモニタ ROM のクローン。bank_init が KEY ルーチンの OUT 9C 値を
  パッチ済み (0xF6→0xFE, 0xF5→0xFD, 0xF3→0xFB: bit3=1 で拡張 RAM モード維持)。
  VM からは書き換え不要。
- 拡張 RAM 非搭載時は 0x0000-0x7FFF が使えないため、この配置は動作しない。
- 起動スタブ (0x8400) は通常 RAM にあるため、バンク状態に関係なく実行できる。
