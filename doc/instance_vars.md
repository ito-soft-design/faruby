# インスタンス変数 (`@`) の計画と実装

**実装済みです。** 下の「確かめたこと」は実際に走らせた結果で、机上の
見込みではありません。使い方は
[README](../README.md#インスタンス変数-) にあります。

## 結論

**`@foo` は汎用グローバル変数と同じ値スロットに置けます。** 命令は 2 つ足し
ますが、**どちらも中身を書きません** — `OP_GETGV` / `OP_SETGV` の枝へ落とす
前処理にするだけで済みます。

| | |
|---|---|
| 足す命令 | `OP_GETIV` (0x19) / `OP_SETIV` (0x1A) |
| 命令の中身 | **無し。** `OP_GETGV` (0x15) / `OP_SETGV` (0x16) へ落とす |
| メモリ配置 | **変えません。** 汎用グローバルの枠を使います |
| シンボルの種別 | **増やしません。** `SYMBOL_KIND_GLOBAL` のまま |
| 生成コード | **1 命令 4 行** (下記) |

## なぜ 1 つの枠で足りるのか

**self が 1 つしか無いからです。** faRuby にクラスはないので、トップレベルも
メソッドの中もブロックの中も self は `main` です。Ruby でもトップレベルの
`@foo` は `main` のインスタンス変数なので、**名前ごとに 1 つの枠で正しい** —
近似ではありません。

```ruby
@n = 0
def bump
  @n = @n + 1    # self は main。上の @n と同じもの
end
bump
```

`OP_GETIV` と `OP_GETGV` は**どちらも `BB` 形式**で、オペランドは
`(レジスタ, シンボル番号)` です。やることも「シンボル表を引いて値スロットを
写す」で同じなので、枝を 2 つ持つ意味がありません。

## 確かめたこと

### mrbc が出すもの

```
@count = 0
@count = @count + 1
```

```
symbols: ["@count"]
0000  OP_LOADI_0    R[1] = 0
0002  OP_SETIV      @count, R[1]
0005  OP_GETIV      R[1], @count
0008  OP_ADDI       R[1] = R[1] + 1
0011  OP_SETIV      @count, R[1]
```

**`$DM100` の `OP_SETGV` と同じ形**です。シンボル表に `@count` という名前が
入り、命令はその番号を指します。

### いまの faRuby

| 書いたもの | いまの結果 |
|---|---|
| `@count = 0` | **ERROR=26** で停止 (未知のオペコード 0x1A) |
| `@@c = 1` | ERROR=28 で停止 (未知のオペコード 0x1C) |

シンボル `@count` はホスト側で**メソッド名**として扱われています
(`symbol_mapping` の最後の枝)。

### 試作して動いたもの

命令 2 つ、シンボルの振り分け 1 行、生成器 1 箇所を直して確かめました。

| 確かめたこと | 結果 |
|---|---|
| トップレベルの代入と参照 | 通る |
| メソッドの中から同じ `@n` | 通る (3 回呼んで 3) |
| ブロックの中から | 通る (`5.times` で 0+1+2+3+4=10) |
| 配列・文字列・実数を持つ | 通る (`@a.length` が 3) |
| **`nil` から始まる** | 通る。`@once ||= 7` が **7 になる** |
| `$n` と `@n` は別の枠 | 通る |
| `@@c` (クラス変数) | **未対応のまま** (ERROR=28) |

**`||=` が効くのは割り付け表の `nil` 問題との違いです。** 値スロットは型タグを
持つので、`@once` は本当に `nil` から始まります
([ロードマップの `nil` の項目](roadmap.md))。

### 生成コードの増え方

前処理は 1 命令 4 行です (KV-5000)。

```kvs
' OP_GETIV: R[a] = @名前 (OP_GETGV へ)
IF EM6:Z9 = 25 THEN
  EM6:Z9 = 21
END IF
```

**枝は増えません。** 振り分けはオペコードを書き替えた後の `OP_GETGV` が
そのまま拾います。

| 機種 | 増える行 |
|------|---------|
| KV-5000 / KV-X500 | `vm_04_fetch` に +10 |
| MELSEC Q / iQ-R | `vm_02_body` に +10 |

**ただし KV は 13 本すべて取り込み直すことになります。** 命令が 2 つ増えると
組の分け方が変わり、どの命令がどの群のスクリプトに入るかがずれるためです
(行数は入れ替わるだけで、群の合計はほぼ変わりません)。

## 決めておくこと

### 1. `@@` (クラス変数) をどうするか

**コンパイル時に止めます。**

```
ERROR: @@c はクラス変数です。faRuby には未対応です (@c のように 1 つにしてください)
```

いまは ERROR=28 (未知のオペコード) で止まります。**`@` を通すと `@@c` も
`@` で始まるので、振り分けを素通りしてしまいます。** シンボルは枠を取るのに
命令が無い、という中途半端な形になります。

**手間が理由ではありません。** `OP_GETCV` (0x1B) / `OP_SETCV` (0x1C) も
`BB` 形式で、`@` とまったく同じ形で通せます (前処理 2 つ、+8 行)。
やらない理由は 3 つです。

**(1) Ruby 本体が許していません。** トップレベルの `@@` は Ruby 3.0 以降
エラーです。

```
$ ruby -e '@@c = 1'
-e:1:in '<main>': class variable access from toplevel (RuntimeError)
```

通してしまうと、**faRuby でしか動かないプログラム**が書けることになります。
`@` は Ruby でもそのまま動くので、そこが分かれ目です。

**(2) いま入れても `@` と区別が付きません。** クラスが無いので文脈は Object
1 つで、`@@c` も `@c` も「名前ごとに 1 枠」になります。同じものに 2 通りの
書き方ができるだけです。

**(3) クラスと一緒でないと本来の意味になりません。** `@@` はクラスとその
子孫で分け合う変数なので、クラスの表が要ります。先に入れると、クラスを作る
ときに作り替えるものが 2 つになります。

**クラスを入れるときの手間は `@@` そのものではなく継承で決まります。**
継承が無ければ「クラスごとに 1 枠」で済み、`@` と同じ大きさです。継承を
入れると、Ruby は親まで遡って探し、見つかった方を書き替えるので、そこが
手間になります。

### 2. 枠の上限

**`@foo` は `$foo` と同じ 100 個の枠 (`max_globals`) を分け合います。**
その上限はいま検査していません
([ロードマップ](roadmap.md)の「汎用グローバルの個数を検査する」)。101 個目は
配列プールに重なり、**配列を壊しながら動きます。** `@` を入れると名前が
増えやすくなるので、**検査を同時に入れるのが安全です** (ホスト側だけで済む)。

### 3. `:@foo` という書き方

**シンボルの値 (`:foo`) はメソッド名の通し番号です。** `@foo` を枠に回すと
`:@foo` が番号を持てず、`OP_LOADSYM` が止まります。**使う人はまず書かない
形**なので、止まることを文書に書くだけでよいと考えます。

### 4. デバイスへの割り付け

**`@foo` は割り付け表に書けません。** 表は `$` から始まる名前を引くもので、
`@` は通りません。デバイスに乗せたい値は `$name` と書いて表に入れてください
([README](../README.md#変数を実デバイスにする))。

分けたままにする理由は、**`@` は faRuby の中の値、`$` はラダーと分け合う値**
という読み分けができることです。

### 5. `load` で消えること

汎用グローバルと同じく、`load` がスロットを 0 に潰します。**電源を入れ直した
ときも消えます** ([README](../README.md#電源を入れ直したとき))。残したい値は
デバイスに割り付けてください。

## オブジェクトが来たときに変わること

**この形は「self が 1 つ」の間だけ正しいものです。** クラスができて
`Foo.new` が 2 つできた時点で、`@foo` は「どの self のものか」で行き先が
変わります。シンボル表の項目が「スロットのアドレス」ではなく
「インスタンス変数の番号」になり、VM が self の表を引くことになります。

**直すのはこの 2 命令だけです。** `@` を扱う場所がここしか無いので、
作り替える範囲は広がりません。トップレベルの `@foo` も、`main` という
オブジェクト 1 つの表に入るだけになります。

## 入れたときに出てきたこと

**生成器は中身の無い前処理を受け付けませんでした** (`op.body.call` で落ちる)。
オペランドを覗く行も中身がそれを使うときだけでよいので、両方まとめて
「中身があれば」にしました。

**前処理の数を数えていたテストが落ちました。** `loop` のときに入れた
「前処理ごとにスロットのアドレスを組み立てていること」を見るもので、
中身の無い前処理はスロットを触らないので数が合いません。**中身のあるものだけを
数える**形に直し、落とすだけの前処理を見るテストを別に足しました。
