# 対応オペコード一覧

mruby 3.x 可変長バイトコード形式に基づきます。実装済みは 59 命令です。

この一覧は [tools/opcode_table.rb](../tools/opcode_table.rb) の内容を説明する
ものです。命令の追加・変更はそちらを直し、`rake vm_core` で再生成します。

### ロード系

| # (hex) | # (dec) | 名前 | 形式 | 動作 |
|---------|---------|------|------|------|
| 0x00 | 0 | OP_NOP | Z | 何もしない |
| 0x01 | 1 | OP_MOVE | BB | R[a] = R[b] |
| 0x02 | 2 | OP_LOADL | BB | R[a] = Pool[b] |
| 0x03 | 3 | OP_LOADI | BB | R[a] = b (**符号なし** 0-255) |
| 0x04 | 4 | OP_LOADINEG | BB | R[a] = -b (b は符号なし) |
| 0x05 | 5 | OP_LOADI__1 | B | R[a] = -1 |
| 0x06 | 6 | OP_LOADI_0 | B | R[a] = 0 |
| 0x07 | 7 | OP_LOADI_1 | B | R[a] = 1 |
| 0x08 | 8 | OP_LOADI_2 | B | R[a] = 2 |
| 0x09 | 9 | OP_LOADI_3 | B | R[a] = 3 |
| 0x0A | 10 | OP_LOADI_4 | B | R[a] = 4 |
| 0x0B | 11 | OP_LOADI_5 | B | R[a] = 5 |
| 0x0C | 12 | OP_LOADI_6 | B | R[a] = 6 |
| 0x0D | 13 | OP_LOADI_7 | B | R[a] = 7 |
| 0x0E | 14 | OP_LOADI16 | BS | R[a] = signed_int16(b) |
| 0x0F | 15 | OP_LOADI32 | BSS | R[a] = (b << 16) + c |
| 0x11 | 17 | OP_LOADNIL | B | R[a] = nil |
| 0x12 | 18 | OP_LOADSELF | B | R[a] = self (トップレベルでは main) |
| 0x13 | 19 | OP_LOADT | B | R[a] = true |
| 0x14 | 20 | OP_LOADF | B | R[a] = false |
| 0x10 | 16 | OP_LOADSYM | BB | R[a] = symbols[b] (シンボル) |
| 0x51 | 81 | OP_STRING | BB | R[a] = pool[b] の複製 (文字列) |
| 0x1E | 30 | OP_SETCONST | BB | FARUBY_ の設定なら VM 状態へ書く |

`OP_STRING` は**毎回複製します**。Ruby の文字列は変更できるので、同じ
リテラルを 2 回書けば別のものです。**リテラルを書くたびに配列プールを
1 スロット使う**ため、ループの中に書くと使い切ります。

`OP_SETCONST` が見るのは `FARUBY_` で始まる定数だけです。faRuby の設定を
VM 状態へ書きます。それ以外の定数は利用者のものなので何もしません。
走るのは起動時の 1 回だけです。`OP_GETCONST` は実装していないので、
設定を読もうとすると未知のオペコードで止まります。設計は
[文字列の計画](string.md)。

シンボルの値は**ホストが名前ごとに振った通し番号**です。シンボル表は irep ごとに
別なので、オペランドの索引をそのまま値にすると別の irep の同じ名前と等しく
なりません。番号を挟むことで `OP_EQ` の「タグと値の一致」がそのまま使えます。

番号はメソッド表の索引と同じものです (`:foo` と `def foo` は Ruby でも同じ
名前空間)。デバイス名や変数名 (`$DM100`) はシンボルにできず、エラー 3 です。

### 変数アクセス系

| # (hex) | # (dec) | 名前 | 形式 | 動作 |
|---------|---------|------|------|------|
| 0x15 | 21 | OP_GETGV | BB | R[a] = global[symbols[b]] |
| 0x16 | 22 | OP_SETGV | BB | global[symbols[b]] = R[a] |
| 0x23 | 35 | OP_GETIDX | B | R[a] = R[a][R[a+1]] (デバイス・配列・ハッシュ・文字列) |
| 0x24 | 36 | OP_SETIDX | B | R[a][R[a+1]] = R[a+2] (デバイス・配列・ハッシュ) |

`OP_GETIDX` / `OP_SETIDX` は R[a] の型タグで振り分けます。デバイス族なら
下記のデバイスアクセス、配列なら[配列](#配列)、
ハッシュなら[ハッシュ](#ハッシュ)の要素アクセスです。

オペランド `b` は IREP シンボルテーブルのインデックスです。デバイスマッピングテーブルを参照し、対応する PLC デバイスにアクセスします。

- **ワードデバイス** (EM, DM, ZF): 変数名のサフィックスで幅を選択 (既定は `.S` = 16 ビット符号付き)
- **ビットデバイス** (R, MR, B, LR): 個別ビットアクセス (読み取り→true/false、書き込み→非0で ON、0で OFF)
- **ビットデバイス** (T, C): 個別ビットアクセス (書き込みは SET/RES コマンド)
- CR はインデックス扱い不可のため非対応

グローバル変数名の命名規則:
- `$DM100` → DM デバイスのアドレス 100 (ワード、16ビット符号付き)
- `$DM100L` → 同上を 32 ビット符号付きで (DM100/DM101 の 2 ワードを占有)
- `$MR10` → MR デバイスのアドレス 10 (ビット、true/false)
- `$foo` → 汎用グローバル領域に自動割当 (値スロット、32ビット)

アドレスを外した形は「デバイス族」で、添字を付けて実行時にアドレスを決めます。
- `$DM[600 + i]` → DM(600+i) を 16 ビット符号付きで
- `$DML[612]` → DM612/DM613 を 32 ビット符号付きで
- `$MR[64]` → MR400 (添字はデバイス番号)

`OP_GETGV` はデバイス族を読むとき、デバイスにはアクセスせず `TT_DEVICE` の
参照値をレジスタに置きます。`OP_GETIDX` / `OP_SETIDX` がその参照値と添字から
アドレスを組み立てます。

### 配列

| # (hex) | # (dec) | 名前 | 形式 | 動作 |
|---------|---------|------|------|------|
| 0x47 | 71 | OP_ARRAY | BB | R[a] = [R[a] .. R[a+b-1]] |
| 0x48 | 72 | OP_ARRAY2 | BBB | R[a] = [R[b] .. R[b+c-1]] |

実体は固定数のスロットを並べた**配列プール**に置き、レジスタには `TT_ARRAY` と
スロット番号だけを入れます。スロットは順に渡して**返しません**。使い切ると
エラーコード 10 で停止します。設計の経緯は [ヒープの計画](heap.md) にあります。

`OP_ARRAY` は `R[a]` が要素の先頭と結果を兼ねるため、要素を写し終えてから
`R[a]` を書きます。

要素は `OP_GETIDX` / `OP_SETIDX` で読み書きします。範囲外の扱い:

| 書き方 | 動作 |
|-------|------|
| `a[5]` (要素数超え) | `nil` (Ruby と同じ) |
| `a[-1]` | 最後の要素 (Ruby と同じ) |
| `a[5] = 1` (要素数超え) | 伸ばして間を `nil` で埋める。容量まで |
| `a[12] = 1` (容量超え) | エラー 10 |
| `a[-5] = 1` (行き過ぎ) | エラー 2 (Ruby は `IndexError`) |

`length` / `size` / `empty?` / `<<` / `push` はメソッド呼び出しなので
`OP_SEND`、`each` は `OP_SENDB` です
([メソッド呼び出し系](#メソッド呼び出し系))。

### ハッシュ

| # (hex) | # (dec) | 名前 | 形式 | 動作 |
|---------|---------|------|------|------|
| 0x53 | 83 | OP_HASH | BB | R[a] = { R[a] => R[a+1], .. } (b 組) |

オペランド `b` は**組の数**です。1 組が 2 レジスタなので `OP_HASH [2, 3]` は
R[2]-R[7] を読みます。

**実体は配列 2 本です。** 鍵の配列と値の配列で、レジスタには `TT_HASH` と
2 つのスロット番号が入ります。専用のプールを作らないため、確保も容量検査も
配列のものがそのまま効きます。**引き換えにハッシュ 1 つがプールを 2 スロット
消費します。**

引くのは `OP_GETIDX` / `OP_SETIDX` です。**鍵の配列を先頭から順に見ます。**
ハッシュ表は作りません。容量が 12 程度ならハッシュ値を計算するより速いためです。
順序が保たれるのは Ruby と同じです。

**鍵の一致は型と値の両方**です。Ruby の Hash も `eql?` で引くので
`{1 => :a}[1.0]` は `nil` です。ここは合っています。

| 書き方 | 動作 |
|-------|------|
| `h[:z]` (無い鍵) | `nil` (Ruby と同じ) |
| `h[:a] = 1` (既にある鍵) | 値だけ差し替える |
| `h[:b] = 2` (新しい鍵) | 鍵と値の両方の末尾に足す |
| 13 組目 | エラー 10 (1 スロットの容量) |
| プールの空きが 1 つ | エラー 10 (2 つ要る) |

`size` / `length` / `key?` / `keys` / `values` / `each` は組み込みメソッド
として実装済みです。設計は [ハッシュの計画](hash.md)。

### 演算系

| # (hex) | # (dec) | 名前 | 形式 | 動作 |
|---------|---------|------|------|------|
| 0x3C | 60 | OP_ADD | B | R[a] = R[a] + R[a+1] |
| 0x3D | 61 | OP_ADDI | BB | R[a] = R[a] + int(b) |
| 0x3E | 62 | OP_SUB | B | R[a] = R[a] - R[a+1] |
| 0x3F | 63 | OP_SUBI | BB | R[a] = R[a] - int(b) |
| 0x40 | 64 | OP_MUL | B | R[a] = R[a] * R[a+1] |
| 0x41 | 65 | OP_DIV | B | R[a] = R[a] / R[a+1] |
| 0x52 | 82 | OP_STRCAT | B | R[a] = R[a] + R[a+1] (文字列を継ぎ足す) |

`OP_ADD` は文字列どうしなら連結し、**新しいスロットを取ります**。左側は
変わりません。**判定は整数どうしの枝の中**に置いてあります。足し算は最も
多く通る経路なので、手前に比較を足すと全体が遅くなるためです。

`OP_STRCAT` は式展開 (`"x#{s}y"`) が出します。こちらは**継ぎ足す先をその
まま伸ばします**。継ぎ足す先の長さが奇数だとワードの途中から始まるので、
そこはバイト単位で書きます。

### 比較演算系

| # (hex) | # (dec) | 名前 | 形式 | 動作 |
|---------|---------|------|------|------|
| 0x42 | 66 | OP_EQ | B | R[a] = (R[a] == R[a+1]) ? true : false |
| 0x43 | 67 | OP_LT | B | R[a] = (R[a] < R[a+1]) ? true : false |
| 0x44 | 68 | OP_LE | B | R[a] = (R[a] <= R[a+1]) ? true : false |
| 0x45 | 69 | OP_GT | B | R[a] = (R[a] > R[a+1]) ? true : false |
| 0x46 | 70 | OP_GE | B | R[a] = (R[a] >= R[a+1]) ? true : false |

比較結果は整数ではなく `true` / `false` (型タグ TT_TRUE / TT_FALSE) です。

数値は型が違っても値で比べます (`1 == 1.0` は真)。`OP_EQ` だけは数値以外も
扱い、型と値の両方が一致したときだけ真になります (`nil == false` は偽)。

文字列は**中身で比べます**。レジスタに入っているのはスロット番号なので、
番号のままでは同じ内容が等しくなりません。バイト数を先に見て、同じなら
ワード単位で比べます。ハッシュの鍵の一致も同じ判定です。設計は
[文字列の計画](string.md)。

### メソッド呼び出し系

| # (hex) | # (dec) | 名前 | 形式 | 動作 |
|---------|---------|------|------|------|
| 0x2F | 47 | OP_SEND | BBB | R[a] = R[a].symbols[b](R[a+1]..) |
| 0x2D | 45 | OP_SSEND | BBB | R[a] = self.symbols[b](R[a+1]..) |
| 0x30 | 48 | OP_SENDB | BBB | R[a].symbols[b](R[a+1]..) { ブロック } |
| 0x34 | 52 | OP_ENTER | W | 引数の数を検査し、残りのレジスタを空にする |
| 0x38 | 56 | OP_RETURN | B | R[a] を返して呼び出し元へ |
| 0x3A | 58 | OP_BREAK | B | 反復を打ち切って R[a] を返す |
| 0x57 | 87 | OP_BLOCK | BB | R[a] = 子 irep b から作ったブロック |
| 0x58 | 88 | OP_METHOD | BB | R[a] = 子 irep b への参照 |
| 0x5F | 95 | OP_DEF | BB | メソッド表に symbols[b] = R[a+1] を登録 |
| 0x63 | 99 | OP_TCLASS | B | R[a] = 定義先クラス (トップレベルは main) |
| 0x21 | 33 | OP_GETUPVAR | BBB | R[a] = 外側 c 段の R[b] |
| 0x22 | 34 | OP_SETUPVAR | BBB | 外側 c 段の R[b] = R[a] |

`def` は `OP_TCLASS` + `OP_METHOD` + `OP_DEF` の 3 命令になります。詳細は
[メソッド定義・呼び出しの計画](method_calls.md) と
[ブロックの計画](blocks.md) にあります。

**組み込みメソッドは呼び出しフレームを作りません。** 引数は R[a+1] から
連続して並び、結果は R[a] に返るため、その場で計算して置き換えるだけで
済みます。ユーザー定義メソッドとブロックはフレームを積みます。

オペランド `b` はシンボルテーブルのインデックスで、`OP_GETGV` と同じテーブルを
引きます。テーブルの 4 ワード目がシンボル種別で、2 ならメソッド名です。名前は
ホスト側で番号に解決済みなので、VM は文字列を持ちません。

**オペランド `c` は引数の数そのものではありません。** 下位 4 ビットが位置引数の
数、上位 4 ビットがキーワード引数の数で、15 (`CALL_MAXARGS`) は「配列や
ハッシュにまとめて渡す」印です。faRuby が扱う普通の呼び出しでは引数の数と
一致するため `c` をそのまま定義と比べており、スプラットやキーワード付きの
呼び出しは一致せずエラーになります。

組み込みメソッドは **レシーバの型ごとに連続した番号**に並べてあります。
型検査を範囲比較で済ませるためで、並べ替えると壊れます。**タグの側も
連続している**ため (`TT_STRING` 7・`TT_ARRAY` 8・`TT_HASH` 9)、
「文字列と配列」のような組も 1 つの範囲で表せます。並びは
`METHOD_RECEIVER_GROUPS` にあり、生成コードもシミュレータもそこから作ります。

| 番号 | メソッド | 引数 | レシーバ | 動作 |
|------|---------|------|---------|------|
| 1 | `!=` | 1 | すべて | `OP_EQ` の否定 |
| 2 | `!` | 0 | すべて | 偽 (nil / false) なら true |
| 3 | `%` | 1 | 整数 | 商を切り下げた余り。符号は除数に合う |
| 4 | `abs` | 0 | 数値 | 絶対値。型は変わらない |
| 5 | `to_i` | 0 | 数値 | 0 方向へ切り捨て |
| 6 | `to_f` | 0 | 数値 | 実数へ変換 |
| 7 | `floor` | 0 | 数値 | −∞ 方向へ切り下げ |
| 8 | `round` | 0 | 数値 | 0 から遠い方へ丸める |
| 9 | `times` | 0 | 数値 | 0 から n-1 まで繰り返す (ブロック必須) |
| 10 | `upto` | 1 | 数値 | a から b まで繰り返す (ブロック必須) |
| 11 | `&` | 1 | 整数 | ビットごとの積。KV の `AND` |
| 12 | `\|` | 1 | 整数 | ビットごとの和。KV の `OR` |
| 13 | `^` | 1 | 整数 | 排他的和。KV の `XOR` |
| 14 | `~` | 0 | 整数 | ビット反転。KV の `NOT` |
| 15 | `>>` | 1 | 整数 | 右シフト。KV の `SRA` |
| 16 | `length` / `size` | 0 | 文字列・配列・ハッシュ | 要素数 (ハッシュは組の数、**文字列は文字数**) |
| 17 | `empty?` | 0 | 文字列・配列・ハッシュ | 長さが 0 なら true |
| 18 | `<<` | 1 | 整数・文字列・配列 | 整数は左シフト (KV の `SLA`)。文字列は中身を継ぎ足し、配列は末尾に足す |
| 19 | `each` | 0 | 配列・ハッシュ | 順に渡して繰り返す (ブロック必須)。配列は要素、ハッシュは鍵と値 |
| 20 | `push` | 1 | 配列 | 末尾に足してレシーバを返す (Ruby の String に `push` は無い) |
| 21 | `key?` | 1 | ハッシュ | 鍵があれば true |
| 22 | `keys` | 0 | ハッシュ | 鍵を並べた**新しい配列**。1 スロット使う |
| 23 | `values` | 0 | ハッシュ | 値を並べた**新しい配列**。1 スロット使う |

シフトは桁数を 0-31 にしてから `SLA` / `SRA` に渡します。**桁数が負なら
向きを逆にし、32 以上なら振り切った答え** (左は 0、右は符号) を直接置きます。
Ruby がそう振る舞うためで、範囲外の桁数を KV の命令へ渡さない狙いもあります。

ビット演算は KV スクリプトの `AND` / `OR` / `XOR` / `NOT` をそのまま使います。
**これらは式の中でワードに対して書ける演算子**で、条件式の連結には使えません
(そちらは入れ子の `IF` にしています)。シフトは `SLA(元, 桁数, 先)` /
`SRA(元, 桁数, 先)` の文なので、スクラッチへ出してから写します。

**`<<` だけはレシーバのタグが飛びます** (整数 4、文字列 7、配列 8)。区分の
検査は範囲でしか見ないため、実数とシンボルは本体で弾いています。

上記以外を呼ぶと `ERROR` で停止します (code 3)。レシーバや引数の型が扱えない
場合は code 4、`%` の 0 除算は code 1、配列の容量あふれは code 10 です。

`times` / `upto` / `each` は `OP_SENDB` でしか呼べません。ブロック無しで
呼ぶと「未対応のメソッド」で止まります。**レシーバの型で並べたため番号が
連続していない**ので、判定は範囲比較ではなく列挙です。

`loop` は `OP_SSENDB` (self への呼び出し) で別命令のため未対応です。

利用者向けの一覧は [README](../README.md#組み込みメソッド) にあります。
この表は番号と実装の対応で、あちらは書き方と意味です。

### ジャンプ系

| # (hex) | # (dec) | 名前 | 形式 | 動作 |
|---------|---------|------|------|------|
| 0x25 | 37 | OP_JMP | S | PC += signed_int16(a) |
| 0x26 | 38 | OP_JMPIF | BS | if R[a] が真 then PC += signed_int16(b) |
| 0x27 | 39 | OP_JMPNOT | BS | if R[a] が偽 then PC += signed_int16(b) |
| 0x28 | 40 | OP_JMPNIL | BS | if R[a] が nil then PC += signed_int16(b) |

オフセットは符号付き16ビットの相対値です。基点は全オペランドを読み終えた後の PC です。ループ (while) では負のオフセットで後方ジャンプします。

真偽は値ではなく**型タグ**で判定します。Ruby で偽なのは `nil` と `false` だけで、
`0` も真です。タグの並び順が境界になっており (`TT_FALSY_MAX` 以下が偽)、
判定は 1 比較で済みます。`OP_JMPNIL` は `nil` だけを見るので `false` では
飛びません。

### 制御系

| # (hex) | # (dec) | 名前 | 形式 | 動作 |
|---------|---------|------|------|------|
| 0x38 | 56 | OP_RETURN | B | return R[a] (トップレベルでは VM 停止) |
| 0x69 | 105 | OP_STOP | Z | VM 停止 |

### 命令形式の読み方

- **Z** : オペランドなし (1バイト)
- **B** : 8ビットオペランド1つ (2バイト)
- **BB** : 8ビットオペランド2つ (3バイト)
- **BS** : 8ビット + 16ビットオペランド (4バイト)
- **BSS** : 8ビット + 16ビット + 16ビットオペランド (6バイト)

16ビットオペランドはビッグエンディアンで格納されます。

### 注意事項

- オペコード番号は mruby のバージョンによって異なります
- 上記の番号は mruby 3.x 系のものです
- `OP_ADD` 等の算術演算は R[a] と R[a+1] を使い、結果を R[a] に格納します
- mrbc はコンパイル時に定数畳み込みを行うことがあります (例: `1 + 2` が `3` に最適化される)。
  `7 % 3` のような定数どうしのメソッド呼び出しも畳み込まれ、`OP_SEND` になりません
- 値は型タグ付きで保持します (`nil` / `true` / `false` / 整数 / 実数 / デバイス参照)。
  真偽判定はタグで行うため、`0` も `if` では真になります
- 整数は 32 ビット符号付き、実数は IEEE754 単精度です。混在する演算は実数になります
