# 確認の進め方

**シミュレータでは再現できない不具合が何度も出ています。** 16 ビット符号
なしの回り込み、`INC` が 32 ビットかどうか、機種ごとの実数→整数の丸め方、
絶対アドレスと添字の食い違い — どれも実機で初めて壊れました。**VM を直したら
実機で通してから完了にします。**

## PC 上のテスト

```bash
rake test
```

生成結果の突き合わせ、コード生成、シミュレータでの実行が入ります。生成物が
手で編集されていないかもここで見ます。

## 実機での確認

```bash
rake hw
```

**[test/ruby_programs/](../test/ruby_programs/) を順に PLC で走らせ、見出しに
書いた期待値と突き合わせます。** 相手は `connections.current` の PLC で、
`rake hw CONNECTION=KV_X500` のように選べます。1 本だけなら
`rake hw ONLY=test_16` です。

**期待値はプログラムの見出しに書きます。** 別に表を持つと、片方だけ直して
気づかない形になります。

```ruby
# 対象機種: KV-5000        省略するとどの機種でも走らせる
#
# 期待値:
#   $DM520F = 3.0    実数の加算 2.5 + 0.5
#   $DM526  = 3      実数をワードデバイスへ書くと0方向へ切り捨て
```

**機種で触れるデバイスが違うので、走らせる相手も分かれます。** タイマ・
カウンタは KV-5000 だけ、`_melsec` の付いたものは三菱 2 機種だけです。

## 数えている値

| 機種 | 一致した値 |
|------|----------|
| KV-5000 | 225 |
| KV-X500 | 223 |
| MELSEC Q | 223 |
| MELSEC iQ-R | 223 |

KV-5000 が 2 つ多いのはタイマ・カウンタのぶんです。ほかの 3 機種では
そのデバイスを触れません (VM の違いではありません)。
