# 文字列の計画

ロードマップ [項目 6](roadmap.md) のうち String の設計メモです。まだ実装して
いません。Array と Hash が終わり、残るのはこれだけです。

## 逆アセンブルで分かったこと

mrbc 3.3.0 の出力です。

```
s = "hello"            OP_STRING [1, 0]        R[1] = pool[0] の複製
"x#{s}y"               OP_STRING + OP_STRCAT を 2 回
s + t                  OP_ADD    [8]           ← 数値と同じ命令
s * 2                  OP_MUL    [12]          ← 同上
s == "hello"           OP_EQ     [8]           ← 同上
s[0]                   OP_GETIDX [8]           ← 配列・ハッシュと同じ命令
s.length / s.size      OP_SEND
s << "z"               OP_SEND (<<)
s.empty? / s.include?  OP_SEND
["a", "b"]             OP_STRING を並べて OP_ARRAY2
{ "x" => 1 }           OP_STRING + OP_HASH
```

**新しい命令は `OP_STRING` (0x51) と `OP_STRCAT` (0x52) の 2 つだけ**です。
残りはすべて実装済みの経路に枝を足す形になります。Array・Hash と同じ形です。

### 見落とせない点が 3 つあります

**1. `OP_STRING` は毎回複製します。** Ruby の文字列は変更できるので、
同じリテラルを 2 回書けば別のものになります。`s = "a"; t = "a"; s << "b"` で
`t` が変わってはいけません。**リテラルを書くたびにプールを 1 スロット使う**
ということで、ループの中に文字列リテラルを書くと使い切ります。配列リテラルと
同じ制約です。

**2. `==` は中身で比べます。** 今の `OP_EQ` は型と値の一致で、文字列の値は
スロット番号です。別のスロットに入った同じ内容が等しくなりません。
**ハッシュの鍵**も同じ (`find_hash_key`) なので、両方に枝が要ります。

**3. 定数プールに入りません。** 値スロットは 4 ワードで、文字列は入りません。
バイトコードと同じように**FM に文字列定数の領域**を作り、値スロットには
「先頭位置と長さ」を入れます。

## 決めること

### 文字コード — 変換しない。種別だけ覚える

**バイト列は一切変換しません。** mrbc が定数プールに入れたバイトをそのまま
持ち、そのままデバイスへ書きます。**デバイスの文字コードはソースの文字コード
で決まります。** 表示器が Shift_JIS なら、ソースを Shift_JIS で保存するだけです。

覚えておくのは**文字コードの種別 1 ワードだけ**です。ホストがマジックコメントを
読んで書き込みます。無ければ UTF-8 とみなします。扱うのは ASCII・Shift_JIS・
UTF-8 の 3 つで、それ以外は転送前に止めます。

種別が要るのは `length` と `[]` のためです。文字の切れ目が分からないと
文字数を数えられません。

#### mrbc はマジックコメントを見ていません

定数プールに入るのは**ソースファイルのバイト列そのまま**です。実測しました。

| ソース | 定数プールのバイト |
|-------|------------------|
| UTF-8 | `e3 81 82 41` (UTF-8) |
| UTF-8 + `# encoding: utf-8` | `e3 81 82 41` (UTF-8) |
| Shift_JIS | `82 a0 41` (Shift_JIS) |
| Shift_JIS + `# encoding: shift_jis` | `82 a0 41` (Shift_JIS) |
| Shift_JIS + `# coding: windows-31j` | `82 a0 41` (Shift_JIS) |

マジックコメントの有無で何も変わりません。指定に従って変換しているのでは
なく、読んだバイトを写しているだけです。**マジックコメントを読むのは faRuby
の仕事**ですが、読んだ結果でバイト列を変換はせず、種別として記録するだけです。

#### 変換表を持たないと決めた理由

一度は「プログラムに出てくる文字だけの変換表を FM に置き、デバイスへ出すとき
Shift_JIS に直す」形を検討しました。**やめました。**

- 表示器が Shift_JIS なら、**ソースを Shift_JIS で保存すれば変換自体が要りません**
- 実行時に UTF-8 を復号して表を引く処理が、デバイスへ書くたびに走ります
- 「表に無い文字」という新しい止まり方が増えます
- FM を食います

全部を載せた表はそもそも入りません。JIS X 0208 の漢字は約 7000 字で
14000 ワードほどになり、FM の空きは 1 インスタンスあたり 872 ワードです。

### 置き場所 — 配列プールのスロット 1 つ

Hash と同じく**新しいプールを作りません**。1 スロット 50 ワードのうち、
先頭 2 ワードが見出しで残り 48 ワードを使います。

```
  R[x]  タグ=TT_STRING  下位=スロット番号

  スロット5  バイト数=5  [ 6865 6C6C 6F?? ... ]   "hello"
```

**1 ワードに 2 バイト詰め、先の文字が上位バイト**です。KV-5000 の文字列
デバイスがこの並びだからです。`"ABCDE "` は

```
  4142H  4344H  4520H
```

になります。この形に合わせておけば、**デバイスとの行き来がワード単位の写し**
で済みます。文字列を使う目的の多くがデバイスとのやり取りなので、ここを速く
します。

96 バイトです。ASCII なら 96 文字、日本語なら Shift_JIS で 48 文字、
UTF-8 で 32 文字です。

バイト `i` の取り出しは、ワードが `i / 2`、偶数なら上位 (`w / 256`)、
奇数なら下位 (`w - (w / 256) * 256`) です。

**バイト数が奇数のとき、最後のワードの下位バイトは 0 です。** KV-5000 の
文字列デバイスがそうなっています。faRuby はバイト数を見出しに持っている
ので中では要りませんが、デバイスへ書いたときにそのまま終端になります。

### デバイスへの書き込み — 2 つの形

```ruby
$DM100   = "abc"    # 終端付き
$DM100T6 = "abc"    # 固定長。ASCII で 6 文字ぶん
```

**終端付きは新しい書き方が要りません。** 値が文字列かどうかは実行時のタグで
分かるので、`$DM100 = "abc"` は文字列として書く、で決まります。実数と整数を
型で分けているのと同じ形です。

バイト列の後ろに 0 を 1 つ足して書きます。ワードに満たない分は 0 で埋めるので、
3 バイトなら 2 ワード、4 バイトなら 3 ワードになります。

**固定長はサフィックス `T` に長さを付けます。** 長さは **ASCII での文字数**
です。半角 1 文字が 1 で、漢字は 1 字で 2 を使います。表示器の桁数に合わせて
書く形になります。

- 文字列が短ければ、**余りを `FARUBY_STR_FILL` で埋めます**
  ([下記](#faruby_str_fill-で埋め方を選ぶ))。
  埋めないと前に書いた長い文字列の尻尾が残ります
- **ちょうどなら終端を書きません**。書くと次の桁にはみ出します
- **入りきらなければ切り詰めます**。桁に入るところまで書きます。多バイト文字の
  途中で切れて表示器に半端な文字が出ることもありますが、**止めるよりは書く**
  ほうを採ります。桁の数は表示器の都合で決まっていて、そこに収まらない文字列を
  渡すのはよくあることだからです
- 長さが奇数のときは最後のワードの下位バイトが桁の外に出ます。ワード単位で
  しか書けないため、ここには 0 を入れます

長さはシンボル表に詰めます。エントリの `access_type` は 0-5 しか使っていない
ので、`access + 長さ * 16` で 1 ワードに入ります。デバイス参照が種別と幅を
詰めているのと同じ手です。

サフィックスの解析は今 `_?([SULDF]?)` なので、ここに `T` と数字を足します。
16 進アドレスの `$B1T` でも `T` は 16 進数字でないため曖昧になりません。

#### `FARUBY_STR_FILL` で埋め方を選ぶ

固定長で余った桁を何で埋めるかは、**プログラムの先頭で定数として書きます**。

```ruby
FARUBY_STR_FILL = 0x20   # 空白で埋める。既定は 0x00
```

表示器によって都合のよいほうが違うため、設備ごとに選べるようにします。
**終端付きの書き込みには効きません。** あちらの埋めは終端そのものなので 0 です。

`FARUBY_STR_FILL = 0x20` は `OP_LOADI` + `OP_SETCONST` になります。faRuby は
`OP_SETCONST` を未実装なので、ここで実装します。

- ホストがシンボル表に**設定という種別**を足し、設定番号を振る
- VM は `OP_SETCONST` で番号を見て、VM 状態の 1 ワードに値を書く
- `FARUBY_` で始まって知らない名前は転送前に止める。実行時に気づくより早い
- `FARUBY_` で始まらない定数は利用者のものなので、放っておく

**走るのは起動時の 1 回だけ**で、デバイス書き込みの経路には何も足しません。
設定を増やしたくなったときも、名前を足すだけで済みます。

`OP_GETCONST` は実装しません。設定を読む必要が無いためです。

#### なぜ接頭辞か

faRuby の設定であることが見て分かるようにします。`_` を頭に付ける形は
使えません。**Ruby の定数は大文字始まりでないといけない**ので、`_STR_FILL`
はローカル変数になります。実測すると `OP_LOADI` が 1 つ出るだけで、
`OP_SETCONST` もシンボル表の項目も現れません。**faRuby からは存在しないのと
同じ**です。

| 書き方 | 出るもの |
|-------|---------|
| `_STR_FILL = 0x20` | `OP_LOADI` だけ。名前が残らない |
| `FARUBY_STR_FILL = 0x20` | `OP_SETCONST`。名前も残る |
| `STR_FILL_ = 0x20` | `OP_SETCONST`。名前も残る |
| `FaRuby::STR_FILL = 0x20` | `OP_GETCONST` + `OP_SETMCNST` の 2 命令 |

名前空間で分ける形も書けますが、命令が 2 つに増えるうえモジュールを表す値も
要ります。**印を付けるだけなら接頭辞のほうが安く済みます。**

### 長さは文字数

`"あ".length` は Ruby では 1 です。バイト数ではありません。**Ruby に
合わせます。** 先頭から走査して文字の切れ目を数えます。

| 文字コード | 数え方 |
|-----------|-------|
| ASCII | バイト数がそのまま文字数 |
| UTF-8 | 継続バイト (`10xxxxxx`) 以外を数える |
| Shift_JIS | 先導バイト (0x81-0x9F, 0xE0-0xEF) なら 2 バイト進む |

どちらも範囲比較 1 つで、走査の形は同じです。`s[0]` も同じ走査で切れ目を
見つけます。96 バイトなので走査は高々 96 回です。

**Shift_JIS は自己同期しません。** 後続バイトの範囲が ASCII と重なるため、
バイト 1 つを見ても先導か後続か分かりません。必ず先頭から走査します。
UTF-8 は途中から見ても分かりますが、揃えて先頭から走査します。

### `==` と鍵の一致

`OP_EQ` に文字列の枝を足し、バイト数が同じならワード単位で比べます。
2 バイト詰めなので、比較の回数はバイト数の半分で済みます。

ハッシュの鍵も同じ判定にします。`find_hash_key` は今「タグと値の両方」で
比べていますが、文字列だけは中身を見る枝が要ります。

## 進め方

1. **リテラルと代入** — 文字コードの種別を記録する。FM の文字列定数領域、
   `OP_STRING`、`OP_MOVE`、`OP_SETCONST` (`FARUBY_STR_FILL`)。
   デバイスへの書き込み (`$DM100 = "abc"` と `$DM100T6 = "abc"`)
2. **比較と連結** — `OP_EQ` / `!=`、`OP_STRCAT`、`+`、ハッシュの鍵
3. **メソッド** — `length` / `size` / `<<` / `empty?`、`[]` (文字単位)
4. **デバイスから読む** — デバイス文字列を faRuby の文字列にする

段階 1 が終われば実機で「文字列を作ってデバイスへ書く」が通ります。
そこが一番使う形です。

## 先送りする論点

**`*` (繰り返し)。** `s * 2` は `OP_MUL` です。数値の掛け算の枝に文字列の
判定が入るので、**最も多く通る経路が長くなります**。後回しにします。

**`sub` / `gsub` / `upcase` などの加工。** どれも新しいスロットを取ります。
使う場面を見てから決めます。

**書式化 (`format` / `%`)。** 数値を文字列にする `to_s` が要ります。
桁を出す処理を KV スクリプトで書くことになるので、独立した段階にします。

**文字コードをまたぐ比較。** faRuby は 1 プログラム 1 ソースなので、
リテラルどうしなら必ず同じ文字コードです。デバイスから読んだものと比べる
場合だけ食い違い得ますが、その文字列も同じ表示器のものなので実質揃います。

## 確認が要ること

- 設定の定数を他にも用意するか。`FARUBY_` の形が使えると分かれば、
  今 faruby.yml にあるもののうちプログラム側で決めたいものを移せます
- 96 バイトで足りるか。足りなければスロットを大きくするか、複数スロットに
  またがる形を考えることになります
- `OP_STRING` がリテラルごとにスロットを使うため、16 スロットがどれくらい
  持つか。ループの中のリテラルは特に危ない
