# クラスの計画

ロードマップ [次に考えること](roadmap.md#次に考えること) の設計と実装の
記録です。

**段階 3 まで実装済みです** — クラスを定義し、`new` でオブジェクトを作り、
インスタンス変数がオブジェクトごとに別になります。残っているのは
クラス変数 (`@@`) だけです。

**決めたこと** — 継承は入れません。`max_classes` は 8 (0 行目が `main` な
ので使えるのは 7)、`max_methods` は 32 で、表は 256 ワードです。

## 逆アセンブルで分かったこと

mrbc 3.3.0 の出力です。**足りないのは 3 命令だけでした。**

```ruby
class Counter
  def up
    1
  end
end
$DM100 = Counter.new.up
```

```
irep 0  OP_LOADNIL  [1]
        OP_LOADNIL  [2]
      * OP_CLASS    [1, 0]      0x5C  R[1] = Counter クラス
      * OP_EXEC     [1, 0]      0x5E  子 irep 0 を R[1] を self として実行
      * OP_GETCONST [1, 0]      0x1D  R[1] = Counter
        OP_SEND     [1, 1, 0]         new
        OP_SEND     [1, 2, 0]         up
        OP_SETGV    [1, 3]
irep 1  OP_TCLASS   [1]               定義先クラス
        OP_METHOD   [2, 0]
        OP_DEF      [1, 0]
irep 2  OP_ENTER    [0]
        OP_LOADI_1  [2]
        OP_RETURN   [2]
```

| 命令 | | |
|------|---|---|
| `OP_CLASS` | 0x5C | クラスを作って R[a] に置く |
| `OP_EXEC` | 0x5E | クラス本体の irep を R[a] を self として実行 |
| `OP_GETCONST` | 0x1D | R[a] = 定数 (クラス) |
| `OP_SETCV` / `OP_GETCV` | 0x1C / 0x1B | クラス変数 (`@@`)。別立て |

**`OP_SCLASS` は出ませんでした。** `class << self` を書いたときのもので、
ふつうのクラス定義には現れません。`OP_MODULE` / `OP_OCLASS` も同じです。

### 既にあって、そのまま効くもの

**クラス本体はトップレベルの `def` と同じ仕組みです。** irep 1 が
`OP_TCLASS` / `OP_METHOD` / `OP_DEF` で、これはトップレベルに `def` を
書いたときとまったく同じ並びです。**`def` の機構は作り直しになりません。**

| | |
|---|---|
| `new` | ただの `OP_SEND`。専用命令ではない |
| `initialize(n)` | `OP_ENTER [262144]` (必須引数 1 個)。実装済み |
| メソッドの中の `@n` | `OP_GETIV` / `OP_SETIV`。実装済み |
| `OP_TCLASS` | 実装済みだった。`R[a] = R[0]` に変えた |
| 呼び出しフレーム | 実装済み。`OP_EXEC` も `new` もこれに乗る |

**`attr_accessor` は見送りです。** `OP_SSEND` で `attr_accessor` を呼び、
引数が `OP_LOADSYM` の `:n` です。**メソッドを定義するメソッド**なので、
組み込みから `OP_DEF` 相当を起こすことになります。読み書きのメソッドを
自分で書けば済むので、優先度は低いままにします。

## 決まること

### `OP_TCLASS` は self を返すだけでよい

いまは「常に `main`」ですが、**`R[a] = R[0]`** にすると両方正しくなります。
クラス本体の中では self がそのクラス (`OP_EXEC` がそう置く)、トップレベルでは
`main` です。1 行で済み、いまの動きも変わりません。

### クラスは実行時に作らない

`OP_CLASS` は実行時にクラスを作る命令ですが、**faRuby ではクラスは
コンパイル時に分かります。** ホストがクラスに番号を振ってシンボル表に入れて
おけば、`OP_CLASS` と `OP_GETCONST` はどちらも「シンボル表から番号を読んで
R[a] に置く」だけになります。

`OP_EXEC` だけは本体を実行する必要があります (中の `OP_DEF` がメソッドを
登録するため)。これはフレームを 1 つ積んで子 irep へ飛ぶだけで、
**メソッド呼び出しと同じ経路**です。

### `@foo` の行き先はコンパイル時に決まる

**ホストは「どの irep がどのクラスのメソッドか」を知っています。** だから
`@n` が「そのクラスの何番目のインスタンス変数か」をコンパイル時に解決でき、
**実行時に名前を探す必要がありません。**

実行時に見るのは self の型だけです。

| self | `@n` の行き先 |
|------|-------------|
| `main` (`TT_OBJECT`、値 0) | いまと同じ汎用グローバルのスロット |
| オブジェクト | そのオブジェクトの n 番目の値スロット |

枝が 1 つ増えるだけで、名前の照合は入りません。

### オブジェクトは配列プールに入る

プールのスロットは **見出し 4 ワード + 値スロット 12 個 = 52 ワード**です。
オブジェクトは見出しにクラス番号を入れ、値スロットをインスタンス変数に使えば
**1 スロットにそのまま収まります** (インスタンス変数 12 個まで)。

配列・文字列・ハッシュと同じ置き場所で、`TT_OBJECT` の値にスロット番号を
入れる形も `TT_ARRAY` と同じです。**新しい領域は要りません。**

代わりに、32 スロットを配列・文字列・ハッシュ・オブジェクトで**分け合います**。
オブジェクトを 10 個作れば配列は 22 個までです。

### `new` はフレームの種別を 1 つ足せば書ける

`Counter.new(5)` は `OP_SEND` なので、組み込みメソッドとして受けます。やるのは
**オブジェクトを確保して `initialize` を呼ぶ**ことです。

問題は戻り値です。ふつうの `OP_RETURN` は呼ばれた側の `R[a]` を `R[0]`
(呼んだ側の `R[a]`) へ写すので、`initialize` の戻り値がオブジェクトを
上書きしてしまいます。

**先例があります。** 反復のフレーム (種別 1-4) は写さずに「`R[0]` に残った
レシーバがそのまま呼び出しの値になる」形です。`new` 用の種別を 1 つ足して
同じ扱いにすれば、確保したオブジェクトが残ります。`initialize` が無ければ
呼ばずに終わります。

## 決めないといけないこと

### メソッド探索 — ここが唯一の作り直し (実装済み)

いまのメソッド表は **ID → irep の 1 本の表**で、ID はホストが名前ごとに
振っています。**クラスが 2 つ以上あると、同じ名前で衝突します。**

```ruby
class A
  def value    # ← 同じ名前
    1
  end
end
class B
  def value    # ← 同じ ID になってしまう
    2
  end
end
```

**呼ぶ側はレシーバのクラスを知りません。** `c.value` の `c` が A か B かは
実行時に決まるので、探索は実行時です。表を「クラス × 名前」にします。

```
irep = メソッド表[クラス番号 * max_methods + メソッドID]
```

実行時の費用は掛け算 1 回と足し算 1 回です。**いまの表は可変領域に
64 ワードあり、クラス数の倍になります。**

名前を 32 にしたときの大きさです (変える前は名前 64 の 1 本 = 64 ワード)。

| クラス数 | メソッド表 | 可変領域の予備 (520 ワード) |
|---------|----------|--------------------------|
| 4 | 128 ワード | 残り 456 |
| **8** | **256 ワード** | **残り 328** ← これにした |
| 16 | 512 ワード | 残り 72 |

**8 クラス × 32 名前 (256 ワード) にしました。** 既存の 40 本と装置
プログラムを数えたら、名前の数は最大 13、`def` された名前は最大 10 で、
既定の 64 は実測の 5 倍ありました。**削るならクラスより名前**です —
名前は超えたらコンパイル時に止まり、クラス数は設計の自由度に直結します。
予備は 520 → 328 ワードで、ブロックは 4000 ワードのままです。

### 継承を入れるか — 入れないと決めた

**入れないほうが安く済みます。** 入れると 2 か所に効きます。

- **探索に親を遡る繰り返しが入る** — 呼び出しごとに回ります。いまは表を
  1 回引くだけです
- **インスタンス変数の並びが親から続く** — 子のクラスは親の枠の後ろに
  自分のぶんを置くことになります

**`class Sub < Base` をコンパイル時に止める**のが、いまの `@@` と同じ扱いで
一貫します。後から入れるときに要るのは、クラスの表に親の列を足すことと
探索の繰り返しだけで、**置き場所の作り直しにはなりません。**

### クラス変数 (`@@`) は継承次第

継承が無ければ **クラスごとに 1 枠**で済み、インスタンス変数と同じ仕組みを
オブジェクトではなくクラスで引くだけです。`OP_SETCV` / `OP_GETCV` の 2 命令を
足せば動きます。継承を入れると親まで遡るところが要ります。

## 進め方

**4 段階に分けます。** どれも実機で確かめられる単位です。

1. ~~**クラスを作ってメソッドを定義する**~~ — 実装済み。`OP_CLASS` (0x5C) /
   `OP_GETCONST` (0x1D) / `OP_EXEC` (0x5E) を足し、`OP_TCLASS` を
   `R[a] = R[0]` に変え、メソッド表を クラス × 名前 にした。
   **`Counter#up` と `Other#up` が別の行に入ることを確かめた**
   ([test/test_classes.rb](../test/test_classes.rb))
2. ~~**`new` と `initialize`**~~ — 実装済み。プールのスロットを 1 つ取り、
   見出しにクラス番号を入れ、`initialize` があれば呼ぶ。戻り値で
   上書きされないよう `FRAME_KIND_NEW` を足した
3. ~~**`@` をオブジェクトごとに**~~ — 実装済み。**命令には枝を足して
   いません** — シンボル表の種別 (`SYMBOL_KIND_IVAR`) で分かれるので、
   `OP_GETGV` / `OP_SETGV` の種別の振り分けに 1 本増えるだけ。実行時に
   self の型を見る必要もない (ホストがクラスを知っているため)。
   `a.value` と `b.value` が別の値を返すことを確かめた
4. **クラス変数 (`@@`)** — 継承を入れないなら安い

**継承は 5 段階目にしません。** 入れるかどうかを決めてから、別に考えます。

## 費用の見積もり

| | |
|---|---|
| 命令 | 3 つ (`OP_CLASS` / `OP_EXEC` / `OP_GETCONST`)。`@@` を入れるなら 5 つ |
| 作り直し | メソッド表 (1 本 → クラス × 名前)。**ここだけ** |
| 可変領域 | メソッド表がクラス数の倍。予備 520 ワードから出す |
| 固定領域 | クラスの表 (クラスごとにインスタンス変数の数など数ワード) |
| 速度 | 呼び出しに掛け算 1 回と足し算 1 回。`@` に枝 1 つ |
| 生成物 | 4 機種とも出し直し。**実機確認も 4 機種**(VM を触るため) |

**`@` の割り付け表に効きます。** [割り付け表は `@` でも引けます](../README.md#-でも引けます)
が、これは「self が `main` 1 つだけ」に乗っています。オブジェクトが 2 つ
できた時点で名前からデバイスを引けなくなるので、**表に載せられるのは
`main` の `@` だけ**という制限が要ります。
