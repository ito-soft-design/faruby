# ヒープの計画

ロードマップ [項目 5](roadmap.md) の設計メモです。段階 4 (`each`) まで
実装し、実機で確認済みです。

## 何が必要か

Array / String / Hash に共通する置き場所です。これまでの値は 32 ビットに
収まり、レジスタの値スロット (4 ワード) にそのまま入っていました。配列は
入りません。**どこかに実体を置き、レジスタにはその場所だけを入れる**
必要があります。

```ruby
a = [1, 2, 3]
$DM100 = a[0]
```

## 逆アセンブルで分かったこと

mrbc 3.3.0 の出力です。

```
a = [1, 2, 3]          OP_LOADI_1 [2] / OP_LOADI_2 [3] / OP_LOADI_3 [4]
                       OP_ARRAY2  [1, 2, 3]    R[1] = [R[2], R[3], R[4]]
a = []                 OP_ARRAY   [1, 0]       R[1] = [R[1]..R[1+0-1]] = []
a[0]                   OP_GETIDX  [2]
a[1] = 9               OP_SETIDX  [3]
a << 1                 OP_SEND    [2, sym(<<), 1]
a.push(2)              OP_SEND    [2, sym(push), 1]
a.length               OP_SEND    [2, sym(length), 0]
[1,2,3].each { }       OP_ARRAY + OP_BLOCK + OP_SENDB
```

`OP_ARRAY [a, b]` は `R[a] = [R[a] .. R[a+b-1]]`、
`OP_ARRAY2 [a, b, c]` は `R[a] = [R[b] .. R[b+c-1]]` です。

**思ったより既存の仕組みに載ります。**

- `OP_GETIDX` / `OP_SETIDX` は**実装済み**です。今はデバイス参照だけを
  受けているので、型タグが配列のときの枝を足すだけです
- `<<` / `push` / `length` は `OP_SEND` です。組み込みメソッドの
  振り分けに番号を足すだけです
- `each` は `OP_SENDB` です。ブロックと反復フレームは**実装済み**です。
  `times` との違いは、ブロックに渡すのが添字ではなく要素という点だけです

新しく要るのは `OP_ARRAY` / `OP_ARRAY2` と、実体の置き場所です。

見落とせない点が 1 つあります。**リテラルは要素の数だけレジスタを使います。**
`[1,2,...,10]` は `nregs=12` でした。深い呼び出しの中で大きなリテラルを
書くとレジスタ窓があふれます (エラーコード 5)。

## PLC で GC が難しい理由と、今回それが当てはまらない理由

普通の mark-sweep が組み込みで嫌われるのは、**停止時間が読めない**からです。
faRuby はスキャンタイムを守る必要があるので、これは致命的に見えます。

ただし faRuby の事情は違います。**ヒープが固定長なので、一時停止の上限が
最初から計算できます。** 走査する根も小さく、固定です。

| 根 | 数 |
|----|----|
| レジスタ | `max_regs` (既定 80) スロット |
| グローバル変数 | `max_globals` (既定 100) スロット |
| プール内の配列 | スロット数 × 容量 |

C のスタックもクロージャもスレッドもありません。**「どこから参照されて
いるか分からない」場所が無い**ため、走査は上の表を数えるだけで尽きます。

つまり「GC は PLC に持ち込めない」ではなく、「**上限が計算できる GC なら
持ち込める**」が正しい整理です。とはいえ、まず GC 無しで足りるかを見ます。

## 案

### 案 1 — 生成場所にスロットを固定する (GC 無し)

配列の身元をバイトコード上の生成場所で決めます。`OP_ARRAY` が同じ位置に
ある限り、何回実行しても同じスロットを書き直します。ループの中で作っても
使用量が増えません。

```ruby
i = 0
while i < 3
  a = [i, i]      # OP_ARRAY2 は 1 か所。3 回とも同じスロット
  i = i + 1
end
```

生成場所は irep ごとに連続するので、IREP テーブルに `最初の生成場所` を
持たせれば `first_child` と同じ手で引けます。表は生成場所の PC を並べた
1 ワード × 個数だけです。

**採らない理由。** 次が黙って違う答えになります。

```ruby
pairs = []
3.times do |i|
  pairs << [i, i]     # 3 つとも同じ配列。結果は [[2,2], [2,2], [2,2]]
end
```

PLC で**黙って違う答え**を出すのは、止まるより悪いと考えます。

### 案 2 — 順に取り、使い切ったらエラー (GC 無し)

プールの先頭から順に渡し、返しません。使い切ったらエラーで停止します。
Ruby としての意味は正しく、足りなければ**大きな音で**分かります。

```ruby
pairs = []
3.times do |i|
  pairs << [i, i]     # 正しく 3 つ。プールを 3 つ消費する
end
```

`while true` の中で毎周作る書き方はいずれ止まります。これは PLC の
プログラムとしてはもともと避けるべき書き方で、**確保をループの外に
出す**よう促されるのは妥当だと考えます。

### 案 3 — 使い切ったらマークスイープ

案 2 の上に足します。プールが尽きたときだけ走らせ、根から辿って
届かないスロットを回収します。届けば案 2 と同じ、届かなければ
エラーの代わりに回収が起きるだけで、**意味は変わりません。**

一時停止は上表の合計で決まります。既定値なら
`80 + 100 + スロット数 × 容量` ワードの走査です。

## 進め方

**案 2 から始め、案 3 は必要になってから足します。**

案 2 と案 3 の間に意味の違いが無いことが決め手です。案 2 で書いた
プログラムは案 3 でもそのまま動き、エラーが出なくなるだけです。逆に
案 1 を選ぶと、後から直したときに答えが変わります。

段階:

1. **プールと `OP_ARRAY` / `OP_ARRAY2`** — 確保と型タグ。使い切ったら
   エラー — **実装済み**
2. **`OP_GETIDX` / `OP_SETIDX` の配列対応** — 既存の命令に枝を足す。
   範囲外の扱いを決める (Ruby は読みは `nil`、書きは伸長) — **実装済み**
3. **組み込みメソッド** — `length` / `size` / `<<` / `push` — **実装済み**
4. **`each`** — `OP_SENDB` の反復にブロック引数が要素になる形を足す —
   **実装済み**

1 が終われば単体テストで確かめられます。2 以降は Ruby のプログラムから
届きます。

### 段階 1 でしたこと

- 配列プールを可変領域 (EM) の汎用グローバル変数の後ろに置いた。
  `max_arrays` (16) × `max_array_len` (12) で 800 ワード。
  **1 インスタンスは 1000 → 2000 ワード**になり、2 インスタンスで
  EM20000-EM23999 を使う
- `ARRAY_SP` (VM 状態 +39) が次に渡すスロット番号。順に渡して返さないため
  減ることはなく、`max_arrays` に達したらエラーコード 10 で停止する
- `OP_ARRAY` は `R[a]` が要素の先頭と結果を兼ねるため、**要素を写し終えて
  から `R[a]` を書く**。先に書くと 1 要素目が壊れる
- 入れ子の配列は外側のスロットに `TT_ARRAY` + スロット番号が入る。
  `[[1,2],[3,4]]` は 3 スロット使う

**要素数 0 のとき「要素数 - 1」を計算してはいけません。** EM は16ビット
符号なしなので 0 - 1 が 65535 になり得ます。`FOR Z4 = 0 TO 65535` が
回ることになるため、引き算を要素数が 1 以上のときだけ行う形にしました。
シミュレータでは -1 になって空回りするだけで、**実機でしか壊れません**。
生成コードを読むテストで固定しました。

### 段階 2 でしたこと

`OP_GETIDX` / `OP_SETIDX` に型タグが配列のときの枝を足しました。デバイス族の
経路はそのままです。

範囲外の扱いは Ruby に合わせました。

| 書き方 | Ruby | faRuby |
|-------|------|--------|
| `a[5]` (要素数超え) | `nil` | `nil` |
| `a[-1]` | 最後の要素 | 同じ |
| `a[-5]` (行き過ぎ) | `nil` | `nil` |
| `a[5] = 1` (要素数超え) | 伸ばして間を `nil` | 同じ。ただし容量まで |
| `a[12] = 1` (容量超え) | 伸びる | **エラー 10** |
| `a[-5] = 1` (行き過ぎ) | `IndexError` | **エラー 2** |

**`OP_SETIDX` は Z1 に配列、Z2 に添字、Z3 に書き込む値を載せています。**
スロットの見出しをここに置くと、値を書く前に壊れます。最初 Z3 に置いて
しまい、生成コードを読んで気付きました。配列の枝は Z4 以降だけを使います。
テストで固定しました。

添字が使えるようになったので、Ruby のプログラムから確かめられます。

### 段階 3 でしたこと

`length` / `size` / `<<` / `push` を組み込みメソッドに足しました。
`size` は `length` と、`<<` は `push` と同じ番号です。`push` は Ruby と同じく
**レシーバ自身を返す**ので、`R[a]` は配列のままにします。

**メソッド番号の並べ方を変えました。** これまでは「数値レシーバを要求する
メソッドを連続した番号に並べ、型検査を 1 比較で済ませる」でしたが、配列と
いう 2 つ目のレシーバ型が入ったため**レシーバの型ごとの範囲**にしました。

| 番号 | レシーバ | メソッド |
|------|---------|---------|
| 1-2 | 問わない | `!=` `!` |
| 3-10 | 数値 | `%` `abs` `to_i` `to_f` `floor` `round` `times` `upto` |
| 11- | 配列 | `length` `push` |

数値は範囲比較 (2 回)、配列は末尾なので 1 回で決まります。

**ブロックを取るメソッドが連続しなくなりました。** `times` / `upto` は
数値の範囲に、`each` (段階 4) は配列の範囲に入るためです。`OP_SENDB` の
「ブロックを取るメソッドか」の判定は `METHOD_BLOCK_MIN` との 1 比較から、
`BLOCK_METHODS` を並べる形に変えました。

#### 踏んだ不具合

**数値かどうかの判定が「`TT_INTEGER` 以上」でした。** タグは
`TT_INTEGER` = 4、`TT_FLOAT` = 5 の次に `SYMBOL` `STRING` `ARRAY` と続くので、
**配列を数値として通していました。** `[1].abs` がエラーにならず、配列の
スロット番号を整数として計算していたことになります。

数値タグが 2 つしかなく隣り合っているうちは上限を見なくても動いていた
だけで、配列を入れた時点で表に出ました。上限も見るようにしています。

### 段階 4 でしたこと

`each` を足しました。**反復の仕組みは `times` のまま**で、違うのはブロックに
渡す値だけです。

```ruby
[1, 2, 3].each do |v|
  s = s + v
end
```

添字を数えるところは同じで、ブロックに渡すときにその位置の要素を読みます。
**どちらを渡すかはフレームの種別で決めます。**

| 種別 | | ブロックに渡す値 |
|------|--|----------------|
| 0 | 通常の呼び出し | (反復しない) |
| 1 | `times` / `upto` | 添字 |
| 2 | `each` | その位置の要素 |

1 以上が「反復中」なので、`OP_RETURN` / `OP_BREAK` / `OP_ENTER` の判定は
等値から範囲比較に変えるだけで済みました。真偽判定のタグ順と同じ手です。

**要素を読むための配列は `R[0]` から取ります。** レジスタ窓は `R[a]` まで
ずれており、`R[0]` は呼んだ側の `R[a]` すなわちレシーバです。反復が終わった
ときに `R[0]` がそのまま呼び出しの値になる仕組みが既にあり、**ブロックの
実行中も `R[0]` が保たれる**ことに依存しています。フレームを 1 ワード
増やして配列を覚える必要はありませんでした。

### 実機で確認したこと

段階 1-4 をまとめて確認しました
([test_21_arrays.rb](../test/ruby_programs/test_21_arrays.rb))。全 45 件。

- 添字の読み書き・負の添字・範囲外の `nil`・伸長と隙間の `nil`・入れ子・
  ブロックの中での読み書き・メソッドが返した配列・デバイスの値を要素にする
- `length` / `size` / `<<` / `push`、ループで詰めてから合計する
- `each` (要素を渡すこと・空配列・引数なし・`break`・入れ子・メソッドの
  中・要素が `nil`・`times` との併用)
- 要素が 32 ビット整数 (100000) と単精度実数 (2.5) でも通る
- 容量いっぱい (12 要素) の配列と、スロット 16 個ちょうどの消費
- エラー 12 件 (プール使い切り・要素数超え・代入と `<<` の容量超え・
  負で範囲外・型違いのレシーバ 4 種・ブロックの有無)
- **1 インスタンス 2000 ワードになった後のインスタンス 1** (EM21000 →
  EM22000 へ移った) でも配列が動く
- ブロックの回帰 (test_20)

実行速度は 32,711 命令/秒、スキャン周期 1.53 ms。配列を入れる前
(32,449 命令/秒、1.54 ms) と変わりません。**命令を分岐の連鎖の末尾に
足す限りスキャンタイムは延びません。** 計測に使う四則演算 (60-70) より
後ろに `OP_ARRAY` / `OP_ARRAY2` (71・72) を置いたためです。

## 決めること

### 配列の表し方

値スロットは 4 ワードです。デバイス参照と同じく、**下位ワードにスロット
番号**を入れます。型タグは `TT_ARRAY` を新設します。

スロットの中身:

| ワード | 内容 |
|-------|------|
| +0 | 要素数 |
| +1 | 予備 |
| +2~ | 要素 (値スロット 4 ワード/要素) |

要素を 4 ワードにするのは、レジスタ・定数プール・グローバル変数と同じ形に
するためです。既存の値の読み書きがそのまま使えます。3 ワードに詰めると
1 要素あたり 1 ワード浮きますが、専用の読み書きが要ります。

### 容量

**全スロット同じ容量**にします。可変長にすると空き管理が要り、
断片化の面倒を PLC に持ち込むことになります。

### メモリ

配列は実行中に変わるので **EM** です。現在の空きは 1 インスタンス
あたり **40 ワード**しかないため、1 インスタンスの大きさを広げます。

スロット 1 個 = `2 + 容量 × 4` ワード。

| スロット数 | 容量 | プール | EM 合計 | 切り上げ後 | |
|-----------|------|-------|--------|-----------|---|
| 8 | 12 | 400 | 1360 | 2000 | |
| 16 | 12 | 800 | 1760 | 2000 | 採用 |
| 16 | 16 | 1056 | 2016 | 3000 | |
| 32 | 16 | 2112 | 3072 | 4000 | |

対象機のラダーが faRuby 用に確保しているのは EM20000-EM39999
(20000 ワード) です。1 インスタンス 2000 ワードなら 10 個置けるので、
既定の 2 インスタンスには余裕があります。

**16 スロット × 容量 12 (合計 2000 ワード)** を出発点として提案します。
使い切ったらエラーで分かるので、実際のプログラムを見てから増やせます。

### 範囲外アクセス — 決まった

読みは `nil`、書きは容量まで伸ばし、超えたらエラーにしました。
表は[段階 2 でしたこと](#段階-2-でしたこと)にあります。

## 先送りする論点

**String。** 要素が値スロットではなくバイトなので、配列と同じ形には
なりません。文字コードの扱いと、PLC 側の文字列デバイスとのつなぎ方も
決める必要があります。

**Hash。** `OP_HASH` と `OP_LOADSYM` が要ります。キーが Symbol の場合は
シンボル表の索引で足りるため、Symbol 限定なら配列 2 本で作れます。

**`dup` と入れ子。** `a = [[1,2],[3,4]]` は `OP_ARRAY` が 3 回走るので
3 スロット使います。動きますが、消費が見えにくくなります。

**代入は参照。** `b = a` は同じスロットを指します。案 2 では回収が
無いため、これ自体は問題になりません。案 3 に進むときに効いてきます。

- ~~`each` のブロック引数を要素にする変更が、`times` の反復フレームに
  そのまま載るか~~ → 載った。フレームの種別を 1 つ増やしただけ
